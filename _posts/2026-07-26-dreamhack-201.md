## **1. APT 패키지 관리**
### 패키지
리눅스 패키지(Linux Package) : 리눅스에서 프로그램을 실행하기 위해 필요한 파일들의 집합을 포함하는 설치 파일, 크게 소스 패키지(Source Package)와 바이너리 패키지(Binary Package)로 구분

### 소스 패키지  
장점 : 사용자가 소스코드를 자유로이 변경하여 원하는 형태로 프로그램 개조 가능  
단점 : 사용자가 직접 해당 패키지를 컴파일해야 하므로 설치 시간 오래 걸림, 컴파일 과정 중 오류 발생 확률이 존재

## 바이너리 패키지
이미 컴파일 된 바이너리를 제공하기 때문에 설치 시간도 적게 걸리고 오류 발생 확률이 적음
바이너리가 필요로 하는 의존성 파일들을 제대로 제공하지 않는 경우 오류 발생
- 패키지 의존성(Package Dependency) : 관련 패키지가 설치되지 않으면 동작할 수 없을 때 패키지 의존성이 있다고 함
- 패키지 관리자(Package Manager) : 사용자가 설치 시 모든 패키지 의존성을 고려하기 어려워 이를 사용, 저수준 패키지 관리 도구(Low Level Package Tool)과 고수준 패키지 관리 도구(High Level Package Tool)로 나누어짐
- 저수준 패키지 관리 도구 : dpkg(Debian 계열)와 rpm(Red Hat계열)이 있고, 단순히 자신의 패키지를 설치, 제거할 목적으로 사용되며 패키지 간 의존성 고려하지 않음
- 고수준 패키지 관리 도구 : apt, apt-get(Debian 계열)과 yum, dnf(Red Hat 계열)가 있고, 패키지 간 의존성을 관리 도구가 스스로 파악하고 설치

## apt & apt-get
apt-get --(단점 보완)--> apt
- apt-get : 패키지 설치, 업데이트, 삭제만 가능
- apt-cache : 설치할 수 있는 패키지 조회
- dpkg-l : 시스템에 설치된 패키지 조회
- apt : apt-get + apt-cache + dpkg-l, 덜 정밀한 동작 수행하지만 사용자가 사용하기 편리

### apt & apt-get
apt : advanced package tool 의 약자로, 특정 명령어(install, update 등)는 rootㅁ나 사용 가능, apt [옵션] [명령어] 로 사용, 명령어에 따라 조금씩 형태가 달라질 수 있음

- list : 옵션을 만족하는 패키지 목록 출력
- search [명령어] : 검색어를 전체 패키지 목록에서 검사
- show [패키지 이름] : 패키지 정보 출력
- install [패키지 이름] : 패키지를 시스템에 설치
- reinstall [패키지 이름] : 패키지를 시스템에 재설치
- remove [패키지 이름] : 패키지 시스템에서 제거
- update : 패키지를 다운로드하는 저장소의 정보 업데이트
- upgrade : 전체 패키지 업그레이드



- -d : 패키지를 시스템에 설치하지 않고 다운로드만 받기
- -y : 설치 시 사용자에게 설치 여부를 묻지 않고 항상 yes로 생각
- --fix-missing : 패키지를 설치하거나 업데이트할 때 필요한 파일이 누락된 경우 재설치 및 복구를 진행
- --upgradable : list 명령과 함께 사용 시 업그레이드 가능한 패키지 목록 출력
- --only-upgrade : 특정 패키지만 업그레이드
- --arch-only : 특정 아키텍처에 맞는 패키지에만 명령어 적용
- --dry-run : 패키지가 설치될 때의 변경점을 출력하며 실제로 설치하지는 않음
- --purge : 관련 설정파일까지 포함하여 특정 패키지를 완전히 제거


## **2. 네트워크**
- 네트워크(Network) : 그물(Net) + 일(Work)의 합성어로 2개 이상의 컴퓨터들이 서로 통신하기 위해 필요한 모든 것들을 통칭하는 표현
- 프로토콜(Protocol) : 각 계층에서 사용하는 통신 규약, 아래 계층으로 내려갈 때마다 필요한 프로토콜 헤더가 추가되며 위 계층으로 올라갈 때마다 헤더가 제거됨

### OSI 7-Layer Model
- 응용 계층(Application Layer) : 네트워크 서비스를 제공하는 계층, 사용자가 전송하고자 하는 데이터를 해당하는 프로토콜 형식에 맞추어 변환
- 표현 계층(Presentation Layer) : 송수신 과정에서 사용하는 데이터 형식을 통일하는 계층, 수신자와 송신자가 다른 문자나 사진 형식을 사용하는 경우 하드웨어나 운영체제에 따른 차이가 발생하지 않도록 데이터 변환, 암호화나 압축 수행하기도 함
- 세션 계층(Session Layer) : 애플리케이션 간 소통 과정을 지원하는 계층, 송신자와 수신자의 데이터 통신을 동기화하고 오류가 발생한 경우 복구를 수행 (세션 : 수신자와 송신자 간 연결상태) 
- 전송 계층(Transport Layer) : 수신자와 송신자들이 올바른 정보를 송수신할 수 있도록 하며 이를 위해 포트 정보 등을 포함한 세그먼트(segment) 생성, 세그먼트 정보 바탕으로 오류 검출, 복구, 흐름제어 등을 수행
- 네트워크 계층(Network Layer) 또는 인터넷 계층(Internet Layer) : 수신자와 송신자를 구분하기 위해 IP 주소 등을 포함한 패킷(Packet) 생성, 이 정보 바탕으로 라우터가 최적의 경로로 패킷 이동시킴
- 데이터 링크 계층(Datalink Layer) : 물리 데이터가 안전하게 전송되도록 함, 과정에 오류가 있는지 검사하고 재전송하기도 함, 여기서 송수신하는 데이터를 프레임(Frame)이라 하며 네트워크 계층의 데이터에 Media Access Control(MAC) 주소(고유함, 해당 번호로 송신자와 수신자 식별) 등을 붙여 만듦
- 물리 계층(Physical Layer) : 0과 1의 전기적 신호가 케이블을 통해 전달되는 과정

### 네트워크 상태 확인 및 변경
#### 네트워크 인터페이스 확인(ifconfig)
네트워크 인터페이스(Network Interface) : 컴퓨터나 네트워크 장비가 통신하기 위한 물리적 또는 가상의 연결 지점, 네트워크 인터페이스 카드(NIC) 존재, 전기 신호를 디지털 데이터로 변환

ifconfig : interface config의 약자로, 이것만 입력하면 활성화 된 모든 네트워크 인터페이스의 정보가 출력됨

- flags : 인터페이스의 상태
- mtu : 인터페이스의 최대 전송 단위
- inset : 인터페이스에 할당된 IPv4 주소
- netmask : 인터페이스 IPv4에서만 사용하는 기능(ip주소와 netmask를 and연산하여 네트워크 주소 구할 수 있음)
- broadcast : 인터페이스의 브로드케스트 주소
- ether : 인터페이스의 MAC 주소
- RX[packets, bytes, ...] : 받은 패킷 정보
- TX[packets, bytes, ...] : 보낸 패킷 정보
- ifconfig [인터페이스 이름] up : 인터페이스 활성화
- ifconfig [인터페이스 이름] down : 인터페이스 비활성화

### 네트워크 접속(nc)
nc : netcat 의 줄임말로, TCP 혹은 UDP 연결을 읽거나 기록하는 프로그램, nc [옵션] [ip] [port] 로 사용

- -d : 백그라운드 모드로 실행
- -e [프로그램 이름] : 네트워크 연결이 이루어진 경우 주어진 프로그램을 실행
- -o [파일 경로] : 주어진 파일 경로에 통신 데이터를 저장
- -p [포트] : 로컬 포트를 지정
- -s [주소] : 로컬 주소를 지정
- -n : DNS를 사용하지 않음
- -u : UDP 연결을 사용
- -l : 인바운드 연결을 지원하여 listen모드로 실행(수신자 역할을 수행)
- -c : LF(\n) 대신 CRLF(\r\n)을 사용
- -v : 자세한 정보를 출력

### 네트워크 접속(ssh)
ssh : secure shell 의 줄임말로, 사용자는 안전하게 원격으로 셸을 사용할 수 있음, well-known port(사용 목적이 정해진 포트 넘버, 22번), 디피-헬만 키 교환(Diffie-Hellman Key Exchange) 방식을 사용, ssh [옵션] [사용자 이름]@[서버 주소] [명령어] 사용

- -p [포트 번호] : 서버 주소의 포트번호로 접속, 포트 번호를 지정하지 않는 경우 22로 취급
- -v : 연결 과정에 대한 자세한 정보 출력
- -i [private_key 경로] : 비밀번호 대신 private_key를 사용하여 접속
- -X : 접속 시 X11 애플리케이션을 실행할 수 있도록 함
- -L [로컬 포트]:[로컬 주소]:[원격 포트] : [로컬 주소]:[로컬 포트]를 원격 서버의 원격 포트로 포워딩
(로컬 : ssh 클라이언트, 원격 : ssh 서버)
- -R [로컬 포트]:[로컬 주소]:[원격 포트] : [로컬 주소]:[로컬 포트]를 원격 서버의 원격 포트로 포워딩
(로컬 : ssh 서버, 원격 : ssh 클라이언트)
- -C : 데이터를 압축하여 네트워크 성능을 향상

### 파일 다운로드(wget)
wget : web get 의 약자로, 웹 상의 파일을 다운로드 받기 위한 명령어, HTTP, HTTPS, FTP 프로토콜을 사용하는 사이트의 파일들 다운로드 가능, wget [옵션] [URL] 로 사용

- -O : 다운로드한 파일의 파일명 지정
- --limit-rate=N : 다운로드 시 속도 제한
- -b : 백그라운드에서 다운로드
- -d : 디버그 내용 출력
- --reject=[확장자] : 특정 확장자만 제외하고 다운로드
- -r : 재귀적으로 탐색하여 파일 다운로드

### 네트워크 데이터 전송(curl)
curl : client URL 의 약자로, 특정 프로토콜을 이용해 URL로 데이터 전송, 서버에 데이터를 보내거나 가져올 때 사용, curl [옵션] [URL] 로 사용

- -k : HTTPS를 사용하는 경우 인증서에 대한 검증 없이 연결
- -i : HTTP 헤더 정보만 출력
- -L : HTTP 301, 302를 받은 경우 리다이렉션 URL로 이동
- -d [데이터] : HTTP POST 데이터를 전송
- -o [파일 이름] : curl로 받아온 내용을 파일로 저장
- -X [메소드] : 주어진 메소드(GET, POST, DELETE 등)로 요청
- -A [이름] : User-Agent 정보 전송
- -H [헤더] : 전송 시 사용할 헤더 정보 저장
- -u [이름]:[암호] : 접속 시 이름과 비밀번호가 필요한 경우 사용
