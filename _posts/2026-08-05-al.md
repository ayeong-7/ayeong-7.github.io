# 1. 컴퓨터 과학 기초
## 1-1. 컴퓨터 과학 기초
### 진법
한 자릿수에 표현할 수 있는 숫자의 개수, n진법은 한 자릿수를 n가지(0 ~ n-1)의 숫자 혹은 문자로 나타낼 수 있음
- 2진법 : 0, 1 2개의 숫자로 수를 표현
  - 비트(bit) : 0과 1의 조합
  - 바이트(byte) : 비트 8개
  - 2진수를 표현할 때는 보통 0b라는 접두어 붙임
- 10진법 : 0 ~ 9 10개의 숫자로 수를 표현
- 16진법 : 0 ~ 9, A ~ F 16개의 숫자로 수를 표현
  컴퓨터는 2진법을 사용하지만, 2진법은 수가 조금만 커져도 표현할 때 많은 숫자가 필요하여 비효율적이고, 사람이 읽고 쓰기 어려움 -> 16진법 사용

### 비트와 바이트
- 1 비트(bit, binary digit) : 컴퓨터에서 사용하는 데이터의 최소 단위
- 1 바이트(byte) : 8개의 비트로 구성된 더 큰 단위, 메모리에 저장되는 최소 단위, 2^8=256가지의 수 표현
- 16진수 한 자리 = 2진수 네 자리
- 최상위 비트(MSB, Most Significant Bit) : 이진 데이터에서 가장 왼쪽에 있는 비트
- 최하위 비트(LSB, Least Significant Bit) : 이진 데이터에서 가장 오른쪽에 있는 비트

### 부호 비트 
부호가 있는 데이터 : MSB는 부호의 의미를 가짐. 0이면 양수, 1이면 음수.  
부호(+, -)를 가지는 데이터 = Signed 데이터 또는 부호가 있는 데이터
부호 없이 양수만 나타내는 데이터 = unsigned 데이터 또는 부호가 없는 데이터

### 바이트 오더링(Byte Ordering)
2 바이트 이상의 데이터는 메모리에 연속적으로 저장되는데, 이때 각 바이트가 메모리에 정렬되는 방식  
빅 에디안(Big Endian), 리틀 에디안(Little Endian) 2가지 방식이 있음  
*비트의 순서가 아니라 바이트의 순서를 고려하는 것으로, 바이트 내 비트의 순서는 동일하고, 바이트의 순서만 달라짐
- 빅 엔디안(Big-endian) : 가장 왼쪽에 있는(큰) 바이트부터 메모리의 낮은 주소에 저장됨, 네트워크 상에서 데이터를 전송할 때 사용
- 리틀 엔디안(Little-endian) : 가장 오른쪽에 있는(작은) 바이트부터 메모리의 낮은 주소에 저장됨, 대다수의 개인용 컴퓨터 및 서버 환경에서 사용됨
- 예시
1. 리버스 엔지니어링 : 메모리에 저장된 값을 이용해 역연산을 수행하여 어떤 정답이 되는 값을 찾아내는 작업을 하는데, 메모리에 저장된 값이 어떤 엔디안을 저장되어 있는지 고려하지 않으면 전혀 다른 데이터로 혼동할 수 있음
2. 시스템 해킹 : 공격을 위해 특정 메모리 주소에 원하는 값을 덮어씌워야 한다고 가정할 때, 메모리의 낮은 주소부터 값을 쓰는 경우에는 리틀 엔디안을 고려하여 저장하려는 값의 가장 오른쪽 바이트부터 써야됨, 어떤 변수의 출력값을 알아내려고 한다면 메모리의 변수 주소 영역에서 높은 주소부터 값을 읽어옴  

문자열을 메모리에 저장할 때는 바이트 오더링을 고려하지 않음 
문자열이 아닌 데이터(ex. 16진수 정수)는 리틀 엔디안 방식으로 저장되어 예를 들어, 0x41424344는 0x44 0x43 0x42 0x41로 저장 되고, 출력하면 높은 주소부터 읽어와서 원래 값 그대로 출력됨

### 비트 연산
피연산자를 2진수로 표현하여 비트(bit) 단위로 연산하는 것. 비트 단위로 논리 연산을 수행하거나 비트를 특정 값만큼 이동하는 시프트(shift) 연산을 수행
- 논리 연산 : 참 또는 거짓 값으로 연산을 수행하고 결과로 참(1, true) 또는 거짓(0, false)을 반환
  - x || y : 둘 중 하나라도 참이면 결과는 참(OR)
  - x && y : 둘 다 참이면 결과는 참(AND)
  - !x : 참이면 결과는 거짓, 거짓이면 결과는 참(NOT)
- 비트 연산자 : 비트 단위로 논리 연산 수행. 1은 참, 0은 거짓
  - x | y :  두 비트 중 하나라도 1이면 결과는 1(OR)
  - x & y : 두 비트 모두 1이면 결과는 1(AND)
  - x ^ y : 두 비트가 같으면 결과는 0, 다르면 결과는 1(XOR)
  - ~x : 비트가 0이면 결과는 1, 1이면 결과는 0으로 모든 비트를 반전시킴(NOT)
- 시프트 연산자 : 비트를 특정 값만큼 왼쪽 혹은 오른쪽으로 이동. n만큼 시프트한 결과는 2^n으로 곱하거나 나눈 값과 같음
  - x << n : 비트를 n만큼 왼쪽으로 이동. 오른쪽 빈 칸은 모두 0으로 채움 == x * 2^n
  - x >> n(산술 시프트) : 비트를 n만큼 오른쪽으로 이동. 왼쪽 빈 칸은 MSB와 동일한 비트 값으로 채움 == x / 2^n
  - x >>> n(논리 시프트) : 비트를 n만큼 오른쪽으로 이동. 왼쪽 빈 칸은 모두 0으로 채움

### 비트 연산 활용
AND(&) 연산을 활용한 비트 마스킹(Bit Masking)
어떤 데이터가 존재할 때, 특정 위치의 비트만 표시하거나 가리는 연산을 비트 마스킹이라 함
- 하위 1 바이트만 가져오기 : 0x000000FF와 AND 연산
- 상위 1 바이트만 가져오기 : 24번 우측으로 논리 시프트 수행, 24번 우측으로 산술 시프트 후 0x000000FF와 AND 연산
- 상위에서 두 번째 바이트 가져오기 : 16번 우측으로 시프트 후 0x000000FF와 AND연산
- 하위 1바이트의 상위 4비트 가져오기  : 4번 우측으로 시프트 후 0x000000FF와 AND 연산
XOR 연산을 활용한 비교와 암호화
자기 자신과 XOR 연산하면 결과는 0. 두 변수에 저장된 값끼리 XOR 연산하여 결과가 0인지 확인하여 두 값이 같은지 비교. 같은 값에 어떤 값을 2번 XOR하면 원래의 값과 동일해짐
시프트 연산을 활용한 곱셈, 나눗셈

### 인코딩, 디코딩
- 인코딩(Encoding) : 데이터를 특정한 형식으로 변환하는 것
- 디코딩(Decoding) : 인코딩 된 데이터를 통해 원래의 값을 구하는 것

### 아스키 코드(ASCII)  
정보 교환을 위한 미국 표준 코드. 문자를 숫자로 변환하는 문자 인코딩(character encoding)의 표준. 아스키 코드를 사용하여 문자를 숫자로 인코딩하면 서로 다른 장치 간 데이터 전송이 더 쉬워짐

### 유니코드(Unicode)
영어 뿐만 아니라 전세계 모든 언어의 문자에 고유한 번호를 부여하는 국제 표준 코드. 서로 다른 언어를 사용할 때 문자가 호환되지 않는 문제를 해결하기 위해 만들어짐. 최대 32비트로 문자 1개를 표현하여 현재 143000개 이상의 문자를 표현할 수 있음

### URL 인코딩(퍼센트 인코딩)
웹 브라우저로부터 받은 URL 문자열을 유효한 형식으로 변환하는 것. URL은 특정한 형식의 문자열을 허용하고, 알파벳 대소문자, 숫자, 일부 특수 문자만을 포함할 수 있기 때문. 즉 :/?#[]@!$&'()*+,;=%공백은 인코딩이 필요

### Base64 인코딩
이진 데이터를 아스키 문자로 구성된 텍스트로 변환하는 인코딩 방식. 총 64개의 아스키 문자가 인코딩에 사용되기 때문에 64진법(Base 64)라는 의미. 64개의 아스키 문자는 알파벳 대소문자(52자), 숫자(10자), +, /
- 인코딩 방식
1. 원본 이진 데이터를 비트 나열로 표현하고, 이를 6비트씩 끊어서 묶음. 만약 비트의 개수가 6의 배수가 아닐 경우 뒤에 0 추가하여 6의 배수로 만듦
2. 각 6비트 묶음을 수로 변환한 뒤, base64 테이블에서 해당하는 문자를 찾아 이로 치환
3. 이렇게 치환 과정을 거친 뒤, 글자 수가 4의 배수가 되도록 문자 '='를 반복해 뒤에 추가(=패딩(Padding))

### 운영체제(OS)
사용자를 위해 특정한 기능을 수행하는 응용 프로그램의 동작을 수행하고, 시스템 자원을 할당하는 등의 복잡한 관리 작업을 하는 소프트웨어. 사용자 및 응용 프로그램과 하드웨어(CPU, 메모리, 입출력 장치 등) 사이에서 중재자 역할 수행
하는 일
- 실행중인 프로그램, 즉 프로세스에 CPU를 번갈아 할당해야 하는데, 이때 어떤 프로세스에 CPU를 할당할지 결정(CPU 스케줄링)
- 메모리 공간을 각 프로세스에 분배하고 사용하는 과정 관리
- 컴퓨터가 입출력 장치와 정보를 주고 받는 과정 관리
- 사용자가 컴퓨터에 명령을 내릴 수 있도록 함(= 셸)

### 커널(Kernel)과 셸(Shell)  
- 커널 : 운영체제의 핵심 기능인 하드웨어 관리를 실제로 수행하는 프로그램
- 셸 : 사용자가 운영체제의 커널 사이에서 사용자가 운영체제에 명령을 내릴 수 있도록 인터페이스 역할  
사용자가 셸에 명령을 입력하면 셸이 명령어를 해석하여 커널에 요청 -> 커널은 명령을 수행하여 하드웨어를 조작하고 수행 결과를 셸에 전송 -> 셸은 이 결과를 해석하여 사용자에게 출력해줌

*운영체제 종류 : Windows, UNIX, Linux, masOC, Android, iOS

# 2. 컴퓨터 아키텍처 기초
## 2-1. Background: Computer Architecture
### 컴퓨터 구조(Computer Architecture)
CPU, 메모리, 입출력 장치와 같은 하드웨어 구성 요소가 어떻게 설계되고 상호작용하는지를 연구하는 학문. 프로그램이 실제로 어떤 과정을 거쳐 기계 수준에서 실행되는지에 대한 큰 그림을 다루는 분야  
컴퓨터의 기능 구조에 대한 설계, 명령어 집합구조, 마이크로 아키텍처, 기타 하드웨어 및 컴퓨팅 방법에 대한 설계가 포함됨. 대표적으로 폰 노이만 구조, 하버드 구조, 수정된 하버드 구조가 있음  
- 명령어 집합 구조(ISA, Instruction Set Architecture) : CPU의 명령어에 대한 설계. CPU가 이해하고 실행할 수 있는 명령어 집합과 해당 명령어들의 동작 방식을 정의한 규약으로, ARM, MIPS, AVR, 인텔의 x86 및 x86-64 등이 있음  
- 마이크로 아키텍처(Micro Architecture) : CPU의 하드웨어적 설게. CPU가 명령어 집합 구조를 어떻게 효율적으로 구현하고 실행할지 CPU의 회로를 설계하는 분야. 명령어를 순서대로 병렬 처리하는 파이프라인(Pipeline), 자주 사용하는 데이터를 임시로 보관해두는 캐시(Cache) 등 성능과 전력 소모에 영향을 미치는 부분들을 다룸(+슈퍼 스칼라, 분기 예측, 비순차적 명령어 처리)

### 폰 노이만 구조(Von Neumann Architecture)
폰 노이만은 컴퓨터에 연산, 제어, 저장의 3가지 핵심 기능이 필요하다고 생각했음. 근대의 컴퓨터는 연산과 제어를 위해 중앙처리장치(CPU, Central Processing Unit)를, 저장을 위해 기억장치(Memory)를 사용. 장치 간 데이터나 제어 신호를 교환할 수 있도록 버스(Bus)라는 전자 통로 사용
- 중앙처리장치 : 프로그램의 연산을 처리하고 시스템을 관리하는 컴퓨터의 두뇌. 프로세스의 코드를 불러오고, 실행하고, 결과를 저장하는 일련의 모든 과정이 CPU에서 일어남. 산술/논리 연산을 처리하는 산술논리장치(ALU, Arithmetic Logic Unit), CPU를 제어하는 제어장치(Control Unit), 필요한 데이터를 저장하는 레지스터(Register) 등으로 구성됨
*기억장치가 있음에도 CPU 안에 레지스터가 필요한 이유는 CPU의 빠른 연산 처리를 위해 데이터의 빠른 교환이 필요하기 때문
- 기억장치 : 컴퓨터가 동작하는데 필요한 여러 데이터를 저장하기 위해 사용. 용도에 따라 주기억장치와 보조기억장치로 분류. 주기억장치는 프로그램 실행과정에서 필요한 데이터들을 임시로 저장하기 위해 사용하며, 램(RAM, Random-Access Memory)가 있음. 보조기억장치는 운영 체제, 프로그램 등과 같은 데이터를 장기간 보관하고자 할 때 사용하며, 하드 드라이브(HDD, Hard Disk Drive), SSD(Solid State Drive)가 있음
- 버스 : 컴퓨터 부품과 부품 사이 또는 컴퓨터와 컴퓨터 사이에 신호를 전송하는 통로. 데이터가 이동하는 데이터 버스, 주소를 지정하는 주소 버스, 읽기/쓰기를 제어하는 제어 버스가 있음. 이 외에도 랜선이나 데이터 전송 소프트웨어, 프로토콜 등도 버스라 함

### 명령어 집합 구조(ISA, Instruction Set Architecture)
CPU가 해석하는 명령어의 집합. 프로그램은 기계어로 이루어져 있는데, 프로그램을 실행하면 이 기계어로 된 명령어들을 CPU가 읽고 처리함. ISA는 기계어를 CPU가 어떻게 해석하고 처리할지 방법을 정의함. IA-32, x86-64(x64), MIPS, AVR 등이 있고, 모든 컴퓨터가 동일한 수준의 연산 능력을 요구하지 않고 컴퓨팅 환경이 다양하기 때문에 다양한 ISA가 있음
- CISC(Complex Instruction Set Computer) : 1970년대에 나온 명령어 집합 구조로, 메모리 효율성에 초점을 맞춰 개발된 구조. 시간이 지나면서 메모리 용량이 늘어 새로운 구조가 만들어짐
- RISC(Reduced Instruction Set Computer) : 1980년대에 나온 명령어 집합 구조로, CISC 구조의 단점을 해결하기 위해 개발됨. 명령어의 개수가 적고 길이가 짧으며, 고정된 길이의 명령어만 사용. 일정한 명령어의 길이로 인해 CPU가 빠르게 디코딩할 수 있고, 전력 효율이 좋기 때문에 저전력 기기에 적합. 명령어가 적어 코드 크기가 커질 수 있고, 어셈블리 프로그래밍이 CISC에 비해 복잡할 수 있음

### x86-64 아키텍처
x86 아키텍처와 호환되는 64비트 아키텍처
- n 비트 아키텍처 : n은 CPU가 한번에 처리할 수 있는 데이터의 크기를 의미
CPU가 한번에 처리할 수 있는 데이터 크기란  
= 레지스터 크키 : CPU 내부의 아주 빠른 임시 저장 공간인 레지스터가 한 번에 저장할 수 있는 데이터의 양  
= ALU 연산 데이터 크기 : CPU 안에 있는 ALU에서 연산할 수 있는 데이터 크기
= 표현 가능한 주소의 크기(데이터의 크기) : 메모리 상의 데이터를 가리키기 위해 사용할 수 있는 주소 범위. 한 번에 접근할 수 있는 메모리 크기  
= 버스의 대역폭 : CPU와 메모리, 다른 부품들 사이에서 한 번에 전송할 수 있는 데이터의 양

### WORD가 크면 유리한 점
WORD : 16bit 부호 없는 정수를 다룰 때 사용하는 자료형
현대 PC는 대부분 64비트 아키텍처의 CPU를 사용하는데, 32비트 아키텍처의 CPU가 제공할 수 있는 가상메모리의 크기(4GB)가 작기 때문. 64비트 아키텍처에서는 이론상 16EB의 가상메모리 제공 가능

### x86-64 아키텍처: 레지스터
레지스터 : CPU가 데이터를 빠르게 저장하고 사용할 때 이용하는 보관소. 산술 연산에 필요한 데이터를 저장하거나 주소를 저장하고 참조하는 등 다양한 용도로 사용. 범용 레지스터(General Register), 세그먼트 레지스터(Segment Register), 플래그 레지스터(Flag Register), 명령어 포인터 레지스터(IP, Instruction Pointer Register)가 존재

### 범용 레지스터(General Register)
주로 데이터 연산을 위해 사용되는 레지스터. 범용이라 다른 용도로도 사용 가능. 8바이트까지 저장 가능하여 부호 없는 정수 기준 2^64 -1까지의 수 저장 가능. x64에서는 r8, r9, r10, r11, r12, r13, r14, r15가 추가로 존재
- rax : Accumulator Register, 함수의 반환 값
- rbx : Base Register, x64에서는 주된 용도 없음
- rcx : Counter Register, 반복문의 반복 횟수, 각종 연산 시행 횟수
- rdx : Data Register, x64에서는 주된 용도 없음
- rsi : Source Index, 데이터를 옮길 때 원본 가리키는 포인터
- rdi : Destination Index, 데이터를 옮길 때 목적지를 가리키는 포인터
- rsp : Stack Pointer, 사용중인 스택의 위치 가리키는 포인터
- rbp : Stack Base Pointer, 스택의 바닥을 가리키는 포인터
*rax = 64비트 전체, eax = 하위 32비트, ax = 하위 16비트, ah = ax 중 상위 8비트, al = ax 중 하위 8비트

### 세그먼트 레지스터(Segment Register)
x86 아키텍처에서 메모리를 세그먼트 단위롤 접근하는 데 사용되는 특수한 레지스터. 16비트 레지스터로는 접근할 수 있는 주소 공간이 작았기 때문에 16비트 범위 밖에 있는 주소에 접근할 때, 어떤 주소가 cs:offset 이라고 하면 cs<<4 + offset으로 계산해 접근할 수 있음
- CS(Code Segment) : 코드 영역. 실행할 코드의 시작 주소
- DS(Data Segment) : 데이터 영역. 프로그램에 지정된 데이터 영역의 시작 주소
- SS(Stack Segment) : 스택 영역. 스택 영역의 시작 주소
- ES, FS, GS : 범용적인 용도로 사용

### 명령어 포인터 레지스터(IP, Instruction Pointer Register)
CPU가 어느 부분의 코드를 실행할지 가리킴. rip이고, 크기는 8바이트

### 플래그 레지스터(Flag Register)
CPU가 연산을 수행한 후 결과의 상태를 저장하는 특수한 레지스터. 특정 연산 후 조건을 판단하는 데 사용되며, 특히 분기, 인터럽트 등에 사용됨. RFLAGS라는 8바이트 크기의 플래그 레지스터가 존재하며, 총 64개 저장 가능. 자신을 구성하는 여러 비트들로 CPU의 현재 상태 표현
### 상태 플래그(Status Flag)  
연산을 수행한 뒤 결과의 상태를 저장하는데 사용
- CF(Carry Flag) : 부호 없는 수의 연산 결과가 비트 범위를 넘을 경우 설정됨
- ZF(Zero Flag) : 연산의 결과가 0일 경우 설정됨
- SF(Sign Flag) : 연산의 결과가 음수일 경우 설정됨
- OF(Overflow Flag) : 부호 있는 수의 연산 결과가 비트 범위를 넘을 경우 설정됨

# 3. Linux 메모리 레이아웃
## Background: Linux Memory Layout
## 리눅스 프로세스의 메모리 구조
### 메모리 레이아웃(Memory Layout)
프로세스가 실행될 때 각 프로세스는 독립된 메모리 공간을 할당받음. 리눅스에서는 프로세스으 메모리를 크게 5가지 세그먼트(Segment)인 코드 세그먼트, 데이터 세그먼트, BSS 세그먼트, 힙 세그먼트, 스택 세그먼트로 구분
- 코드 세그먼트(Code Segment, Text Segment) : 실행 가능한 기계어 코드가 위치하는 영역. CPU가 프로그램을 실행할 때 해당 세그먼트의 기계 코드를 메모리에 올려 실행하게 됨. 읽기, 실행 권한만 주어지고 쓰기 권한은 주어지지 않음(프로그램 코드 수정이 가능해지면 악의적 행위할 가능성 있음)(ex. main())
- 데이터 세그먼트(Data Segment) : 컴파일 시점에 값이 정해진 전역 변수 및 전역 상수들이 위치. CPU는 이곳의 데이터를 읽을 수 있어야 하기 때문에 읽기 권한이 부여되고, 실행 대상이 아니므로 실행 권한은 부여되지 않음. 쓰기가 가능한 세그먼트(Data Segment)는 전역 변수와 같이 프로그램이 실행되면서 값이 변할 수 있는 데이터가 위치. 쓰기가 불가능한 세그먼트(Rodata, Read-only data Segment)에는 프로그램이 실행되면서 값이 변하면 안되는 데이터들이 위치
- BSS 세그먼트(BSS Segment, Block Started By Symbol Segment) : 컴파일 시점에 값이 정해지지 않은 전역 변수가 위치. 프로그램이 시작될 때, 모두 0으로 값이 초기화 됨. 읽기와 쓰기 권한이 부여됨
- 스택 세그먼트(Stack Segment) : 프로세스의 스택이 위치. 함수의 매개변수나 지역 변수 같은 임시 변수들이 실행 중에 이곳에 저장됨. 읽기 권한과 쓰기 권한이 부여됨(해당 세그먼트는 NX(Non-Executable) 보호기법이 나오기 전까지 실행 권한이 존재했지만, 쉘코드(Shellcode)를 이용해 스택에 기계 코드를 넣어 해커가 해당 스택 영역을 호출하는 기법이 나오면서 NX 보호기법을 활성화 시켜 실행 권한을 없앴음)  
스택 프레임(Stack Frame) : 스택을 구성하는 단위. 함수가 호출될 때 전달된 매개변수, 함수가 끝나고 돌아가서 돌아갈 반환 주소, 지역 변수가 저장됨. 함수가 호출될 때 생성되고, 반환될 때 해제됨. 어떤 프로세스가 실행될 때, 이 프로세스가 얼마 만큼의 스택 프레임을 사용하게 될 지를 미리 계산하는 것은 불가능. 운영체제는 작은 크기의 스택 세그먼트를 먼저 할당해주고, 부족해 질 때마다 확장해줌 -> 스택이 확장될 때마다 기존 주소보다 낮은 주소로 확장됨(아래로 자란다)
  *스택 프레임 관리법 : 함수 프롤로그, 함수 에필로그
  - 함수 프롤로그(Function Prologue) : 스택 프레임을 만드는 방법
  - 함수 에필로그(Function Epilogue) : 함수를 종료할 때 스택 프레임을 정리하는 방법
- 힙 세그먼트(Heap Segment) : 힙 데이터가 위치하는 데이터. 실행 중에 동적으로 할당될 수 있으며, 리눅스에서는 스택 세그먼트와 반대 방향으로 자람(힙과 스택이 같은 방향으로 자라고, 연속된 메모리 주소에 할당되면 기존 힙 세그먼트를 모두 사용하고 나면 확장하는 과정에서 스택 세그먼트와 충돌함). 읽기와 쓰기 권한이 부여됨(ex. malloc(), calloc())


# 4. GDB
## 4-1. GDB
버그(Bug) : 실수로 발생한 프로그램의 결함
디버거(Debugger) : 버그를 없애기 위해 사용하는 도구
## GDB 기초 사용 방법
### 파일 불러오기
- file : 디버깅 할 바이너리를 GDB에 불러오기
  *이미 실행 중인 프로세스를 GDB로 디버깅하기 : gdb -p <PID>
실행 흐름 제어하기
- run(r) : 디버거는 기본적으로 프로그램을 실행시키면서 분석하는 도구. 실행 중 특정 지점에서의 프로세스 상태를 진단하고 버그를 찾게 도와줌
- break & continue(b, c) : break는 특정 주소에 중단점(Breakpoint)을 설정하는 기능, continue는 중단된 프로그램을 계속 진행시키는 기능. break로 원하는 함수에 중단점을 설정하고, 프로그램을 계속 실행하면 해당 함수까지 멈추지 않고 실행한 다음 중단됨
  *중단점 설정하는 법 : 함수명과 주소를 이용(ex. pwndbg> b main \n Breakpoint 1 at 0x401156 )
  *continue 여러 번 실행 : continue <숫자>, c <숫자>
- entry & start
리눅스는 실행파일의 형식으로 ELF를 규정함. 헤더에 진입점(EP, Entry Point)이 있고, readelf로 진입점 및 여러 정보를 불러올 수 있음 
entry : 진입점부터 프로그램을 분석할 수 있게 해줌
### 실행 흐름 추적하기
- ni(next instruction, nexti), si(step into, stepi) : 어셈블리 명령어를 한 줄 실행. call 어셈블리 명령어 등을 통해 함수를 호출하는 경우, ni는 함수 내부로 들어가지 않지만, si는 함수 내부로 들어감
- finish : si로 함수 내부에 들어가서 필요한 부분을 모두 분석했는데, 함수의 규모가 커서 ni로 원래 실행으로 돌아가기 어려울 때 finish를 사용하여 함수의 끝까지 한 번에 실행할 수 있음

### 디버깅을 위해 자주 사용하는 명령어들
- info : 정보를 보여주는 명령어
  - info registers(i r) : 프로그램이 실행 중일 때 사용할 수 있는 명령어. 레지스터의 값을 확인하고 싶을 때 사용되고, 레지스터에 들어 있는 값을 바로 사용하고 싶은 경우, $<레지스터명> 형식으로 바로 사용 가능
  - info breakpoints(i b) : 프로그램의 실행 여부와 상관 없이 사용할 수 있는 명령어. break 명령어로 설정한 중단점들 확인 가능. 각 중단점마다 번호가 부여된 것을 알 수 있고, disable 숫자 를 통해 숫자 번중단점을 비활성화. 삭제하고 싶은 경우에는 delete 숫자(d 숫자)를 사용

- disassemble(disass) : 함수 이름을 인자로 전달하면 해당 함수가 반환될 때까지 전부 디스어셈블하여 보여줌(u, nearpc, pdisass : pwndbg에서 제공하는 디스어셈블 명령어, 디스어셈블된 코드를 가독성 좋게 출력)
- x(examine) : 특정 주소에서 원하는 길이만큼의 데이터를 원하는 형식으로 인코딩하여 볼 수 있음. x/<포멧 및 크기>, x/<개수><포멧 및 크기> 형태. 프로그램 실행 도중에만 사용 가능
	x : 16진수, o : 8진수, d : 10진수, u : 부호 없는 10진수, t : 2진수, f : float형, a : 주소, i : 명령어, c : 문자, s : , b : byte, h : halfword(2 byte), w : word(4 byte), g : giant(8 byte)
- telescope(tele) : pwndbg가 제공하는 강력한 메모리 덤프 기능. 특정 주소의 메모리 값들을 보여주고, 메모리가 참조하고 있는 주소를 재귀적으로 탐색하여 값을 보여줌
- vmmap : 가상 메모리의 레이아웃을 보여줌. 어떤 파일이 매핑 된 영역일 경우, 해당 파일의 경로까지 보여줌. 프로그램이 실행된 상태에서 이용 가능
  *파일 매핑 : 어떤 파일을 메모리에 적재하는 것
- backtrace(bt) : 어떤 함수에 전달된 인자에 문제가 발생해 버그가 생겼을 때, 이 인자가 어떤 함수로부터 왔는지 원인을 찾아야하는데 이때 콜 스택을 이용해 확인 가능
콜 스택(Call Stack) : 프로그램이 실행되는 동안 함수가 호출되는 순서를 저장하는 구조. 프로그램이 실행되면서 하나의 함수가 다른 함수를 호출할 때마다 새로운 함수 정보가 추가되며, 함수 실행이 끝나면 가장 최근에 호출된 함수부터 순차적으로 제거됨
- dump memory : 프로세스의 메모리 상태를 파일로 저장할 때 사용. dump memory <파일명> <시작주소> <끝주소> 형식으로 사용
- context(ctx) : 맥락으로, 주요 메모리들의 상태
  - REGISTERS : 레지스터 상태 보여줌
  - DISASM : rip부터 여러 줄에 걸쳐 디스어셈블된 결과 보여줌
  - STACK : rsp부터 여러 줄에 걸쳐 스택 값 보여줌
  - BACKTRACE : 현재 rip에 도달할 때까지 어떤 함수들이 중첩되어 호출됐는지 보여줌
- set : 프로세스의 메모리 상태를 변경. set <주소/레지스터> = <변경할 값> 형식으로 사용


## 4-2. 워게임(Exercise GDB)
### 문제  
GDB로 디버깅하여 플래그를 찾아주세요! flag1과 flag2 2개의 값을 찾아야 합니다.
flag1은 flag_1()가 반환하는 값으로, 해당 함수가 실행된 직후의 rax 값입니다.
flag2는 flag_2()를 실행하면 얻을 수 있으며, flag_2()를 실행하기 위해서는 0x401179 주소에 위치한 명령어가 실행될 때 rax의 값이 0이어야 합니다.
전체 플래그는 DH{flag1-flag2}이며 여기서의 flag1과 flag2 값 모두 "0xdeadbeefdeadbeef"와 같이 18글자의 16진수 문자열로 표현되어야 합니다. 예를 들어 flag1의 값이 0xdeadbeefdeadbeef이고 flag2의 값이 0x1337133713371337이면 전체 플래그는 DH{0xdeadbeefdeadbeef-0x1337133713371337}입니다.

### 풀이  
gdb <바이너리 경로> 를 실행하여 문제 바이너리를 불러온 뒤 b flag_1를 입력하여 flag_1()에 중단점을 걸어준다. 다음으로 run을 실행하여 flag_1()에 도달한 뒤 멈추게되면 finish를 입력하여 이 함수가 끝난 직후 프로세스를 중단시킨다. 그 다음 rax를 확인하기 위해 i r $rax를 입력하면
```
rax            0xc26ff5e224fb0d15  -4436056756304802539 
```
이런 코드가 나오는데 여기서 0xc26ff5e224fb0d15 이것이 flag1이 된다.
0x401179에 중단점을 걸고 실행해야하므로 b *0x401179과 run을 순서대로 입력한다. 여기서 i r $rax로 rax의 값을 확인하면 1이고, set $rax = 0을 입력하여 rax의 값을 0으로 만든다. 그리고 i r $rax를 통해 rax의 값을 확인하면 0이고, 이상태에서 c를 눌러 continue를 진행하면 flag2인
```
flag2 is 0xb81a07bc4181fe49 
```
가 나온다.
따라서 답은 DH{0xc26ff5e224fb0d15-0xb81a07bc4181fe49} 이다.  

### 답 : DH{0xc26ff5e224fb0d15-0xb81a07bc4181fe49}


# 5. NASM
- 어셈블리어(Aseembly Language) : 사람이 읽고 이해할 수 있도록 CPU 명령어를 텍스트 형태로 표현한 저수준 프로그래밍 언어
- 어셈블러(Assembler) : 기계어로 변환하는 역할을 하는 프로그램
- 어셈블(Assemble) : 어세믈리어를 실행 가능한 프로그램으로 만들기 위해서 컴퓨터가 이해할 수 있는 기계어로 바꾸는 과정
- 디스어셈블(Disassemble) : 기계어를 어셈블리어로 바꾸는 것
### NASM 사용법
어셈블러를 사용하여 어셈블리 코드를 실행 가능한 프로그램으로 바꾸기 위해서는
1. 어셈블리 코드 작성
2. 어셈블러를 사용해 어셈블리 코드를 목적 파일(Object file)로 변환
3. 링커(Linker)를 사용하여 실행 파일 생성
*목적 파일(Object file) : 컴파일이나 어셈블 과정에서 소스 코드로부터 생성된 기계 코드를 포함하고 있는 파일. 각 함수나 전역 변수에 해당하는 기계어, 명렁어, 외부 심볼 등이 있음. 파일별로 목적 파일을 만들어 두면 여러 모듈을 독립적으로 컴파일할 수 있어 전체 빌드 시간을 크게 단축하고, 재사용성과 효율성이 향상함
*링커(Linker) : 여러 목적 파일들을 하나로 결합해 최종적으로 실행 가능한 파일 생성. 이 과정에서 각 목적 파일 사이 함수 호출이나 변수 참조 같은 심볼 이름을 연결하고, 각 목적 파일에서 사용하던 상대 주소를 실제 메모리 주소로 재배치함 -> 운영체제가 직접 로드해 실행할 수 있는 독립적인 바이너리가 됨

### 어셈블러를 사용해 코드를 목적 파일로 변환
- -f elf64 : 64비트 ELF 포맷을 지정하여 목적 파일 생성
- -o : 생성할 목적 파일의 이름 지정

### 링커를 사용하여 실행 파일 생성
어셈블리 코드를 목적 파일로 변환한 후, 링커를 사용해 실행 파일 생성
- ld : 유닉스에서 사용할 수 있는 동적 링커의 일종. 목적 파일들을 합쳐 실행 파일로 변환하는 역할

### NASM 옵션
- -f <format> : 어셈블리 코드를 변환할 형식 지정(elf(32비트 ELF 목적 파일), elf64, bin(바이너리 파일), win32(Windows 32비트 목적 파일), win64)
- -o <filename> : 생성될 목적 파일의 이름 지정
- -g : 목적 파일에 디버깅을 위한 심볼 정보 저장
- -I <path> : 외부 파일을 포함할 때 사용(NASM에서는 %include)
- -O<level> : 최적화 수준을 설정할 때 사용(-O1)
- -l<filename> : 리스팅 파일 생성
- -v : NASM 버전 출력
- -E : 프리프로세서만 실행하여 결과 출력
- -P<filename> : 특정 파일을 프리프로세서로 포함
- -X <format> : 링커와의 호환성을 위한 추가 옵션
- -M : 종속성 목록 생성
- -w+error : 경고를 에러로 변환
- -D<macro> : 매크로 정의



# 6. x86 어셈블리
## 6-1. x86 Assembly : Essential Part(1)
### 어셈블리어의 기본 규칙
intel 문법과 AT&T 문법이 있고, NASM은 intel 문법을 사용함

### x86-64 어셈블리어
#### 기본 구조
명령어(Operation Code)와 피연산자(Operand, ex. 레지스터, 상수, 메모리 주소 등)로 구성됨.
피연산자의 개수는 0개 혹은 그 이상이 될 수 있음  
#### 명령어
- 데이터 이동(Data Transfer) : mov, lea
- 산술 연산(Arithmetic) : inc, dec, add, sub
- 논리 연산(Logical) : and, or, xor, not
- 비교(Comparison) : cmp, test
- 분기(Branch) : jmp, je, jg
- 스택(Stack) : push, pop
- 프로시져(Procedure) : call, ret, leave
- 시스템 콜(System call) : syscall
#### 피연산자
상수, 레지스터, 메모리
메모리 피연산자 : []으로 둘러싸인 것으로 표현되며, 앞에 크기 지정자인 TYPE PTR이 올 수 있음. TYPE 위치에는 BYTE, WORD, DWORD, QWORD가 올 수 있으며 각각 1, 2, 4, 8 바이트의 크기를 지정(크기 지정하지 않을 시 오류 발생할 수 있음)
피연산자 표기법 일부(r(8, 16, 32, 64) : 범용 레지스터, imm(8, 16, 32, 64) : 부호있는 정수, r/m(8, 16, 32, 64) 범용 레지스터 혹은 메모리)

### 산술 연산과 논리 연산
add, sub, mul, div
- add : 덧셈. add <destination>, <source>
- sub : 뺄셈. sub <destination>, <source>
- mul, imul : 곱셈. mul <source>
  EAX 레지스터에 보관된 값과 피연산자를 곱하는 명령어. mul은 암시적으로 RAX 레지스터를 첫 번째 피연산자로 사용하고, <source>에 레지스터 또는 메모리 주소를 두 번째 피연산자로 사용  
  - 8비트 x 8비트 : AL 레지스터의 값과 <source> 피연산자의 값 곱하기. 결과값이 최대 16비트이기 때문에 AX에 보관
  - 16비트 x 16비트 : AX 레지스터의 값과 <source> 피연산자의 값 곱하기. 결과값의 상위 16비트는 DX 레지스터, 하위 16비트는 AX 레지스터에 보관
  - 32비트 x 32비트 : EAX 레지스터의 값과 <source> 피연산자의 값 곱하기. 결과값의 상위 32비트는 EDX 레지스터, 하위 32비트는 EAX 레지스터에 보관
  - 64비트 x 64비트 : RAX 레지스터의 값과 <source> 피연산자의 값 곱하기. 결과값의 상위 64비트는 RDX 레지스터, 하위 64비트는 RAX 레지스터에 보관  

  - imul <source> ; 피연산자가 1개
  - imul <destination>, <source> ; 피연산자가 2개
  - imul <destination>, <source>, <immediate> ; 피연산자가 3개
- div, idiv : 나눗셈
  div/idiv <제수>
*mul, div : 부호 없는 연산, imul, idiv : 부호 있는 연산

### and, or, xor, not
- and : 두 개의 비트 모두 1일 때만 결과가 1. AND <destination>, <source>
- or : 하나 이상의 비트가 1이면 결과가 1. 특정 비트 설정할 때 사용. OR <destination>, <source>
- xor : 두 개의 비트가 다를 때만 결과가 1. 비트 토글 및 암호화 등에 사용. XOR <destination>, <source>
- not : 비트 반전. NOT <destination>

### inc, dec
- inc : 1 증가. inc <레지스터/메모리>
- dec : 1 감소. dec <레지스터/메모리>

### 데이터 저장과 이동
- mov : 데이터를 복사/이동하는 명령어. 레지스터 간 혹은 레지스터와 메모리 간에 데이터를 이동시킬 때 사용 가능. source 값을 destination에 대입. mov <destination>, <source> 형식(<destination> : 값을 저장할 목적지(레지스터나 메모리), <source> : 이동할 원본(레지스터, 메모리, 즉시값))
- lea : 메모리에 실제 접근하지 않고, 유효 주소(EA, Effective Address)를 저장하기 위해 사용. lea <destination>, <source> 형식(<destination> : 유효 주소를 저장할 레지스터, <source> : 메모리 피연산자)
  *유효주소란 연산의 대상이 되는 데이터가 저장된 위치
- mov와 lea의 차이 : mov는 메모리에 직접 접근해 값을 가져오지만, lea는 메모리에 접근하는 것이 아닌 단순히 메모리 주소를 계산함

### 비교 연산과 분기문
비교 연산 : 두 피연산자의 값을 비교하고, 플래그를 설정
- cmp : 내부적으로 두 피연산자를 빼는 방식으로 플래그 갱신. cmp <destination>, <source>
- test : 내부적으로 AND 연산한 뒤, 결과는 버리고 플래그 레지스터만 갱신. 보통 특정 비트가 0인지 아닌지 확인하거나 레지스터가 0인지 검사하기 위해 사용. test <destination>, <source>  

분기 : 프로그램의 실행 흐름을 바꾸는 명령어. 명령어 포인터(Instruction Pointer)가 변경됨. jmp <label> 형식
  - jmp : 특정 주소로 rip를 바꿈. 아무 조건 필요 없이 무조건 지정된 주소로 점프
  - je(Jump if Equal) / jz(Jump if Zero) : 직전에 비교한 두 피연산자가 같으면 점프. ZF가 1이면 점프하는 명령어. 두 피연산자의 값이 같을 때 특정 동작을 수행하고 싶을 때 사용
  - jg(Jump if Greater) / jge(Jump if Greater of Equal) : 직전에 비교한 두 연산자 중 전자가 더 크면 점프(ZF==0) && (SF == OF) / 직전에 비교한 두 연산자 중 전자가 더 크거나 서로 같으면 점프(SF = OF)
  - jl(Jump if Less) / jle(Jump if Less or Equal) : 직전에 비교한 두 연산자 중 전자가 더 작으면 점프 (SF != OF) / 직전에 비교한 두 연산자 중 전자가 더 작거나 서로 같으면 점프 (ZF == 1) || (SF != OF)
  - jne(Jump if Not Equal) / jnz(Jump if Not Zero) : 직전에 비교한 두 피연산자가 다르면 점프

### 반복문
비교 연산과 분기문을 적절히 조합해 만들 수 있음.
- 카운터 기반 반복문 : 일정 횟수만큼 반복  
```
 mov rcx, 10  ; 반복 횟수 설정
loop_start:
    ; 반복할 코드
        loop loop_start  ; RCX를 감소시키며 0이 아닐 때까지 반복
```
- 조건 기반 반복문 : 특정 조건을 만족할 때까지 실행  
```
check_condition:
    cmp rax, 50   ; 특정 조건 확인
    jge loop_exit ; 조건이 만족되면 종료
    ; 반복할 코드
    jmp check_condition ; 다시 비교 연산으로 이동
loop_exit:
```
- 후조건 검사 반복문 : 최소 한 번 실행된 후 조건을 검사  
```
do_loop:
    ; 반복할 코드 실행
    cmp rax, 10   ; 조건 검사
    jl do_loop    ; 조건이 만족하면 다시 실행반복문에서 주의할 점  
```

## 6-2. x86 Assembly : Essential Part(2)
### 함수
어셈블리어에서 프로그램이 처리해야 할 명령어들을 한 덩어리로 모아 놓은 코드 블록. 라벨(Label)로 특정 구역을 표시하고 call 명령어 등을 활용해 함수 사용
함수를 호출한 함수(Caller) : call 명령어로 함수를 불러 사용, 호출된 함수(Callee) : ret 명령어를 이용해서 다시 이전 함수에서 실행 중이던 코드로 돌아감

### 스택 관련 명령어
스택 : 자료 구조의 한 종류, 후입선출(Last In, First Out) 방식으로 동작. 데이터를 추가할 때마다 메모리 주소가 감소하며, 데이터를 제거하면 다시 증가함  
주요 요소 : rsp(스택 포인터 레지스터)로, 항상 스택의 가장 위를 가리킴
- push : 스택에 값을 저장하는 명령어. push를 실행하면 rsp가 감소하면서 스택에 값이 저장됨
- pop : 스택에서 값을 꺼내는 명령어. pop을 실행하면 rsp가 증가하면서 스택에 저장되어 있던 값을 꺼낼 수 있음

### 함수 호출 및 반환 관련 명령어
- call : 함수를 호출. 연산 : push return_address \n jmp addr 형식 : call addr
- leave : 프로시저가 반환되기 전, 스택 프레임을 정리. 연산 : mov rsp, rbp \n pop rbp
- ret : 함수에서 반환하여 원래 실행하던 코드로 돌아오기. 연산 : pop rip

### 어셈블리어에서의 함수 선언
1. 함수 시작 위치를 나타낼 라벨 정의
2. 스택 프레임이 필요한 경우, 함수 프롤로그를 통해 스택 프레임 구성
3. 함수 내부에서 실제 동작 구현
4. 함수 마지막에 함수 에필로그를 통해 스택 프레임을 해제하고, ret 명령어로 종료

- x86에서는 cdecl 함수 호출 규약을 통해 함수 선언
- x64에서는 SYSV 함수 호출 규약을 통해 함수 선언

### 함수 호출 과정
- x86에서는 cdecl 함수 호출 규약을 사용할 경우, 함수에 전달할 인자를 스택에 push한 뒤 call 명령어로 함수 호출. 호출 끝난 뒤에는 호출자 측에서 스택 정리를 해줘야 함
- x64에서는 System V AMD64 ABI 함수 호출 규약을 주로 사용. 대부분 정수의 인자가 레지스터를 통해 전달되고, 2개의 인자를 가진 경우, 첫 번째 인자는 rdi, 두 번째 인자는 rsi에 들어감.  
call 명령어는 현재 명령어 직후의 주소를 스택에 저장한 뒤 지정된 라벨로 점프하여 함수 내에서 ret이 실행되면 스택에 저장해 둔 복귀 주소를 꺼내 원래 위치로 돌아오는 구조. 이렇게 함수를 호출할 때마다 콜 스택이 만들어지고, 함수가 반환되면 그 스택도 해제되어 이전 상태로 복원됨

### 시스템 콜
Opcode: 시스템 콜
- 커널 모드(Kernel Mode) : 운영체제가 전체 시스템을 제어하기 위해 시스템 소프트웨어에 부여하는 권한. 모든 메모리 영역에 접근할 수 있고, 하드웨어에 직접적으로 접근할 수 있음. 모든 저수준의 작업은 사용자 모르게 커널 모드에서 진행되고, 시스템의 모든 부분 제어 가능
- 사용자 모드(User Mode) : 운영체제가 사용자에게 부여하는 권한으로, 접근할 수 있는 메모리 영역과 권한이 매우 한정적이고, 하드웨어에 직접적으로 접근할 수 없음
- 시스템 콜(System call, syscall) : 유저 모드에서 커널 모드의 시스템 소프트웨어에게 어떤 동작을 요청하기 위해 사용됨. 소프트웨어 대부분은 커널의 도움이 필요함. 유저 모드에서 할 수 없어 커널이 도움을 요청해야하는데, 이때 도움이 필요하다는 요청을 시스템 콜이라 함. 유저 모드의 소프트웨어가 필요한 도움을 요청하면, 커널이 요청한 동작을 수행하여 유저에게 결과 반환. 사용자는 시스템 콜을 통해 핵심 기능에 접근할 수 있음

### 시스템 콜 사용
- x86
요청하는 시스템 콜 번호 : eax
인자 순서 : ebx -> ecx -> edx -> esi -> edi -> ebp -> ... (시스템 콜의 반환값은 eax 레지스터에 저장됨)

- x64
요청하는 시스템 콜 번호 : rax
인자 순서 : rdi -> rsi -> rdx -> r10 -> r8 -> r9 -> 스택(시스템 콜의 반환값은 rax 레지스터에 저장됨)


# 7. 함수 호출 규약(Calling Convention)
## Background: Calling Convention
### 함수 호출 규약
함수의 호출 및 반환에 대한 약속. 한 함수에서 다른 함수를 호출할 때, 프로그램의 실행 흐름은 다른 함수로 이동하고, 호출한 함수가 반환하면 다시 원래의 함수로 돌아와서 기존 실행 흐름을 이어 나감. 함수를 호출할 때는 반환된 이후를 위해 호출자(Caller)의 상태(Stack frame) 및 반환 주소(Return Address)를 저장해야 함. 호출자는 피호출자(Callee)가 요구하는 인자를 전달해 주어야 하며, 피호출자의 실행이 종료될 때는 반환 값을 전달받아야 함

### x86 호출 규약
대게 레지스터와 스택을 함께 사용. 
- cdecl  
리눅스의 gcc가 x86 바이너리를 컴파일할 때 일반적으로 사용하는 호출 규약. 레지스터 없이 스택만으로 인자 전달. 사용한 스택은 호출자가 정리하고, 스택을 통해 인자를 전달할 때는 마지막 인자부터 첫 번째 인자까지 거꾸로 스택에 push 함
*컴파일(Compilation) : 어떤 언어로 작성된 소스 코드를 다른 언어의 목적 코드로 번역하는 것

- stdcall  
윈도우 API에서 기본적으로 사용되는 함수 호출 규약. 윈도우에서 시스템 호출 효율성을 높이기 위해 cdecl 호출 규약을 변경하여 만듦. 사용한 스택 정리를 호출자가 아닌 피호출자가 함. 마찬가지로 마지막 인자부터 첫 번째 인자까지 거꾸로 스택에 push 함
*retn : 복귀 명령어인 ret은 코드 세그먼트로 복귀하는 retn(near return), 다른 코드 세그먼트로 복귀하는 retf(far return)로 구분. 사용 시 retn 8과 같이 사용하면 복귀와 동시에 스택도 함께 정리할 수 있고, 주로 피호출자가 스택 정리할 때 사용

- fastcall  
함수 호출 시 일부 인자를 레지스터로 전달하여 속도를 향상시키기 위해 도입된 규약. 처음 두 개의 인자를 각각 ecx, edx 에 전달 후 나머지 인자는 마지막부터 스택응로 전달됨

- thiscall  
C++ 클래스 멤버 함수를 위한 함수 호출 규약. 멤버 함수에서 사용하는 this 포인터를 ecx로 넘기고, 나머지 인자들은 모두 스택을 통해 전달

### x86-64 호출 규약: SYSV
SYSV ABI(SYSTEM V Application Binary Interface) 기반으로 만들어짐. ELF 포맷, 링킹 방법, 함수 호출 규약 등의 내용을 갖고 있음
1. 6개의 인자를 RDI, RSI, RDX, RCX, R8, R9에 순서대로 저장하여 전달. 더 많은 인자를 사용할 때는 스택 추가로 이용
2. Caller에서 인자 전달에 사용된 스택 정리(반환 주소 저장, 스택 프레임 저장, 스텍 프레임 할당)
3. 함수의 반환 값은 RAX로 전달됨

### termios 구조체
POSIX 계열 운영체제에서 터미널의 동작 모드를 제어하기 위해 사용하는 구조체. ioctl 시스템 콜을 사용해서 구조체를 제어할 수 있음. 
- c_iflag : 입력이 프로그램에 전달되기 전의 처리 방식 제어
- c_oflag : 프로그램에서 받은 문자가 화면에 출력되기 전의 처리 방식 제어
- c_cflag : 물리적 장치와 통신할 때 데이터 크기, 전송 속도 등을 제어
- c_lflag : 터미널의 특성 제어. 정규 모드와 비정규 모드 전환 가능
- c_cc[NCCS] : 특수 제어 문자의 코드 값을 저장하는 배열. VMIN과 VTIME 사용
  - VMIN : 비정규 모드에서 read 시스템 콜이 언제 반환될지 결정. 해당 항목을 1로 설정하면 문자 하나당 read 가 반환되고, 5로 설정하면 문자 5개가 입력되기 전까지 블로킹됨
  - VTIME : 비정규 모드에서 입력의 최대 대기 시간(Timeout) 설정
### 구현
1. .data/.bss 섹션 정의
*argc : Argument Count의 준말로, 명령줄 인수의 개수를 의미
ANSI 이스케이프 시퀀스(터미널 제어 시퀀스) : 터미널의 특수한 효과를 위해 사용하는 문자 조합. 터미널을 제어하는 문자열을 정의
2. 터미널 설정 
이용자의 입력을 줄 단위로 처리하는 정규 모드가 기본으로 활성화되어 있고, 이 프로그램은 줄 단위가 아닌 문자 단위로 처리할 것이므로, 터미널 모드를 비정규 모드로 변경(변경하는 법 : 터미널 설정을 백업하고 복사본의 c_lflag 필드에서 ICANON 비트를 끄면 기존에 줄 단위로 처리하던 라인 버퍼링이 해제되고 즉시 입력 모드가 되며, ECHO 비트를 끄면 입력된 문자를 화면에 자동으로 출력하지 않게 되며 비정규 모드로 전환 가능)
3. 파일 저장
이용자가 편집을 모두 마친 후, 프로그램을 종료하기 전 작성한 내용과 파일을 저장해야 함. buffer에 작성한 내용을 파일에 쓰는 것과 동이라혐, lseek 호출 없이 buffer 의 내용을 파일에 작성한다면 기존에 존재하던 내용이 중복해서 작성되기 때문에 파일 포인터의 값을 0으로 초기화 해야 함
4. 예외 처리 및 프로그램 종료
5. _start 작성
ESC 문자가 입력될 때까지 입출력을 처리. _start 내부에 키 입력을 처리하고 출력하는 반복문을 작성하고, ESC 문자가 입력될 경우 파일을 저장하거나 프로그램을 종료하도록 코드 작성
5. 키 입력 처리
이용자의 입력을 문자 단위로 처리. key_buf에 이용자에게 입력받은 문자 1개를 저장하고, ESC 문자가 입력된 경우 .handle_esc 레이블로 분기. 일반적인 경우에는 .normal_key 레이블 이하의 코드를 실행하며, buffer에 문자를 추가하고 buf_len 을 1 증가시킨 뒤 해당 문자를 화면에 출력. ESC 가 입력된 경우 파일 저장 및 프로그램 종료를 위해 .handle_esc 레이블로 분기. w가 입력되면 .save_and_continue 레이블로 분기해 파일을 저장하고 입력을 계속 진행하며, q가 입력되면 .save_and_exit 으로 분기해 파일 저장과 함께 프로그램 종료. 그 외의 문자가 입력되면 .normal_key 레이블로 분기해 일반 문자와 동일하게 처리
