### 기초적인 명령어
#### 1. sudo apt update
설치 가능한 소프트웨어 패키지 목록 업데이트

#### 2. sudo apt upgrade
설치된 소프트웨어 패키지의 버전 업그레이드
오래된 소프트웨어 패키지에 존재하는 취약점은 보안 문제를 일으킬 수 있으므로 주기적으로 업그레이드하는 것이 중요

#### 3. id
현재 유저의 유저 ID와 해당 유저가 속해있는 그룹 ID를 출력
리눅스는 권한 기반으로 파일을 읽고 쓰고 실행하기 때문에 자신이 가지고 있는 권한 확인하기 위함

#### 4. pwd
Print Working Directory 의 줄임말로, 현재 작업 중인 디렉토리의 경로 출력

##### 5. ls
List 의 줄임말로, 디렉토리의 내용을 출력
- ls -l : 더 자세한 정보를 함께 출력, 현재 디렉토리 뿐만 아니라 임의 디렉토리도 출력 가능
- ls -l / : 루트 디렉토리의 내용 출력

#### 6. cd
Change Directory의 줄임말로, 작업중인 디렉토리를 변경
절대 경로는 루트 디렉토리 / 를 시작으로 모든 경로를 적어서 표현 (ex. /home/user)
상대 경로는 현재 디렉토리를 기준으로 상위 디렉토리나 하위 디렉토리로 뻗어 나가는 경로

- cd .. : 현재 디렉토리에서 부모 디렉토리로 이동
- cd ~ : 현재 유저의 홈 디렉토리
- cd - : 이전에 위치했던 디렉토리

#### 7. mkdir
Make Directory 의 줄임말로, 디렉토리 생성

#### 8. touch
비어 있는 새로운 파일 생성

#### 9. mv
Move의 줄임말로, 파일이나 디렉토리의 위치를 옮길 때 사용, 파일 이름 변경도 가능

#### 10. rm
Remove 의 줄임말로, 파일이나 디렉토리를 삭제

#### 11. cat
cat 파일경로 형식으로 사용하고, 파일의 내용 출력
(/etc/passwd : 운영체제에 접근할 수 있는 유저 목록 담고 있음)

#### 12. file
파일의 유형 출력, file 파일경로 형식으로 사용
(/bin/ls : ls 명령어를 입력하면 실행되는 실행 파일)

#### 13. echo
셸에 유저가 입력한 텍스트 출력(ex. echo "Hello world!")
echo 명령문 끝에 > 파일명을 이어 붙여 실행하면 파일명을 이름으로 가지는 파일을 생성하고, echo 뒤에 입력한 내용을 파일 내용으로 저장

#### 14. cp
Copy 의 줄임말로, 파일이나 디렉토리를 복사(ex. cp hello world : hello 파일을 world라는 이름으로 복사)
- cp -r : 디렉토리 복사

#### 15. grep
grep 문자열 파일 형식으로 사용, 전체에서 특정 문자열을 찾을 때 사용

#### 16. man
Manual 의 줄임말로, 특정 명령어의 매뉴얼을 보여줌(ex. man cp : cp 명령어의 매뉴얼을 보여줌)

#### 17. curl
client URL 의 줄임말로, 서버에 데이터를 보내거나 서버로부터 데이터를 받는 데이터 전송 명령어
curl [옵션] URL 형식으로 사용(HTTP, HTTPS, FTP 등 다양한 프로토콜)

###### - 주요 [옵션]
- curl URL : 웹 서버의 콘텐츠를 반환하여 출력
- -o file : 전송 받은 데이터를 파일에 저장
- -i : 결과 값에 HTTP 응답 헤더를 포함
- -X "method" : HTTP 요청 메소드 지정
- -d "key=value" : HTTP POST 메소드로 데이터를 전송


### 와일드카드(wildcards)
리눅스에서 임의의 다른 문자를 나타낼 수 있는 특수 문자들로, 주로 명령어를 다른 문자열로 대체하기 위해 사용

- ? : a-z, 0-9 범위 내 임의의 1개 문자로 대체
- \* : a-z, 0-9 범위 내 임의의 0개 문자로 대체
- [] : [문자1-문자2] 혹은 [문자1, 문자2, ...] 형태로 범위 지정

### 리다이렉션(redirection)
모니터에 나타나는 표준 출력 또는 키보드로 입력하는 표준 입력을 다른 곳으로 변경
주로 어떤 명령어의 결과를 파일로 저장하거나 다른 명령어의 입력으로 전달하는 형태로 리다이렉션

- 명령어 > 파일
명령어 표준 출력을 파일로 변경, 파일이 없으면 새로 만들고, 있으면 덮어씀
- 명령어 >> 파일
명령어 표준 출력을 파일로 변경, 파일이 없으면 새로 만들고, 있으면 이어서 씀
- 명령어 < 파일
명령어 표준 입력을 파일로 변경, 파일로부터 표준 입력을 받아 명령어 수행

#### 파이프(pipe)
리다이렉션의 한 형태로, 명령어 결과 표준 출력을 다른 명령어의 표준 입력으로 보낼 때 사용(ex. ls -l | grep hello)


### 권한
#### 유저(user)와 그룹(group)
- 유저는 이름과 고유한 사용자 ID(UID)를 가지고 있음
- 그룹은 여러 유저가 속할 수 있는 그룹으로, 그룹 이름과 고유한 그룹 ID(GID)를 가지고 있음
파일이나 디렉토리와 같은 시스템 자원에 유저가 접근하면 유저의 UID와 해당 유저가 속한 그룹의 GID를 확인하여 정당한 권한을 가지고 있는지 판단하여 접근을 제어

#### 파일 및 디렉토리 권한
각 파일과 디렉토리는 소유자와 소유 그룹을 가지고 있는데, 소유자는 파일 또는 디레고리의 권한을 수정할 수 있는 능력을 가지고 있음. 소유자는 이를 통해 소유자 또는 소유 그룹에 포함된 유저가 해당 파일 또는 디렉토리에 대해 얼마만큼 접근 권한을 가질 것인지 설정 가능.
##### 권한의 종류
- 읽기(Read) : 파일 또는 디렉토리의 내용을 볼 수 있음
- 쓰기(Write) : 파일 또는 디렉토리의 내용을 수정하거나 삭제하는 것을 허용
- 실행(Execute) : 파일이 프로그램인 경우 실행할 수 있게 허용, 디렉토리인 경우, 디렉토리의 내용에 접근할 수 있도록 허용

drwxrwxr-x 2 user user 4096 12월 2 13:38 dir
이는 dir 디렉토리의 예시로, 첫 번째 열은 권한 플래그, 세 번째 열은 소유자, 네 번째 열은 소유 그룹을 나타냄
권한 플래그 : d rwx rwx r-x 이처럼 4부분으로 나눌 수 있는데
d는 디렉토리를, -는 일반 파일, l은 바로가기와 같은 링크 파일
rwx는 소유자의 권한
rwx는 소유 그룹에 포함된 유저들의 권한
r-x는 나머지 유저들의 권한
(권한을 나타내는 3개 문자는 2진수나 10진수로도 표현 가능, rwx : 111 = 7, r-- : 100 = 4)
소유자 : 파일 또는 디렉토리의 권한 플래그 변경 가능, 소유자 또는 소유 그룹 변경 가능
소유 그룹 : 특정 파일 또는 디렉토리에 대한 접근 권한을 편리하게 그룹 단위로 부여하거나 제한 가능

##### 명령어
1. chmod :
chmod 권한 파일명 형식으로 사용, 파일 권한 변경, root 유저 혹은 파일의 소유자만 실행 가능
권한을 표현할 때는 권한 플래그를 10진수로 표현하거나 기존의 권한에 문자를 더하거나 뺌
chmod g+x hello나 chmod g-wx hello 처럼 권한을 변경하거나 제거할 수 있음

2. chown : 
chown 사용자명[.그룹명] 파일명 형식(소유 그룹만 변경하고 싶을 때는 chgrp)으로 사용, 파일 소유자 혹은 소유 그룹을 변경, root 유저만 실행 가능

##### 특수 권한
이를 지정할 때는 권한 플래그 맨 앞에 숫자를 붙여 나타냄
- setuid(4) : 일반 사용자가 파일을 실행하면 파일 소유자 권한으로 실행됨, 소유자의 실행 권한에 x 대신 s 문자로 나타냄
- setgid(2) : 일반 사용자가 파일을 실행하면 소유 그룹 권한으로 실행됨, 소유 그룹 권한에 x 대신 s 문자로 나타냄
- sticky bit(1) : 디렉토리에 설정하면 파일 및 디렉토리 소유자와 root 사용자 외에 일반 사용자가 파일을 삭제할 수 없음, 일반 사용자의 실행 권한에 x 대신 t 문자로 나타냄


#### 디렉토리 구조
루트 디렉토리(/) : 최상위 디렉토리, cd /; ls -l 또는 ls -l / 를 실행하면 루트 디렉토리에 존재하는 파일과 디렉토리들을 볼 수 있음
- /bin : 일반 유저가 사용할 수 있는 기본적인 명령어나 프로그램을 담고 있는 디렉토리
- /boot : 시스템 부팅에 필요한 파일을 담고 있는 디렉토리
- /dev : 컴퓨터에 부착된 장치들을 디바이스 드라이버를 거쳐 파일 형태로 접근 가능한데, 그런 장치들을 나타내는 파일들을 담고 있는 디렉토리
- /etc : 운영체제나 운영체제 위에서 동작하는 서비스의 설정 파일들을 담고 있는 디렉토리
- /home : 각 일반 유저의 홈 디렉토리를 담고 있는 디렉토리
- /lib : 시스템에 필요한 라이브러리 파일들을 담고 있는 디렉토리
- /opt : 소프트웨어 패키지들을 담는 디렉토리
- /proc : 리눅스 커널 자원에 접근할 수 있는 파일과 프로세스를 나타내는 파일을 담고 있음
- /root : root 유저의 홈 디렉토리
- /sbin : 기본적인 유저 명령어나 프로그램을 가지고 있는 디렉토리로, root 유저가 사용할 수 있음
- /tmp : 유저나 프로그램이 임시로 파일을 생성해야할 때 사용할 수 있는 디렉토리, 오래 존재했던 파일들은 자동으로 삭제되므로 주의하여 사용
- /usr : 사용자 바이너리, 문서, 라이브러리, 헤더 파일 등을 담고 있는 디렉토리
- /var : 프로그램이나 시스템이 실시간으로 가변적인 파일을 사용하고 저장해야 할 때 활용하는 디렉토리

## **3. 리눅스 셸**
### 셸(Shell)
운영체제는 크게 유저 레벨(User level), 커널 레벨(Kernel level) 2가지 수준으로 나누어진다. 이 중 사용자가 조작할 수 있는 부분은 유저 레벨이고, 커널 레벨은 조작할 수 없어 운영체제를 온전히 사용하기 위해서는 이를 연결해주는 프로그램이 필요하다. 이 프로그램이 셸이다. 셸의 예시로는 바탕화면, 터미널 화면이 대표적이다.

셸은 영어로 껍질이라는 뜻이고, 사용자가 운영체제와 상호작용할 수 있는 인터페이스를 제공하는 소프트웨어이다. 사용자가 셸에 명령을 입력하면 셸은 이를 해석하여 동작을 수행한다.
셸은 크게 GUI Shell(Graphical User Interface Shell)과 CLI Shell(Command-Line Interface Shell)로 나눌 수 있다.

- GUI Shell  
장점 : 사용자들이 직관적으로 기능을 파악하고 사용할 수 있음
단점 : 실행속도가 느림(그래픽 작업이 CPU나 GPU를 상대적으로 많이 소모)
예시 : Window, macOS의 검색창

- CLI Shell  
장점 : 실행속도가 빠르고 정밀 작업 수행이 편리
단점 : 상대적으로 비직관적임(아이콘과 같은 이미지를 보여주지 않음), 명렁어 암기 필요
예시 : Window의 CMD, macOS의 터미널

- 터미널(Terminal)  
CLI 셸을 GUI 셸 위에서 사용할 수 있도록 하는 프로그램
기본 셸은 bash를 사용하지만, 이 외에도 sh, zsh 같이 다양한 셸이 존재하고 각기 고유한 특징이 있음

- sh  
Bourne Shell(sh)은 유닉스 버전 7의 기본 셸이며, 최초로 사용되던 Thompson Shell, PWB Shell을 대체하기 위해 등장
기능 : 기본적인 프로그램 실행, 기본적인 입출력, 환경 변수 설정, 셸 프로그래밍(if, while 등 지원)

- bash  
Bourne-Again Shell(bash)은 sh를 대체하기 위해 Brian Fox가 작성한 유닉스 셸
GNU 운영체제와 리눅스, macOS 등의 기본 셸로 탑재되었고, 이후 DOS와 Microsoft Windows로도 이식된 매우 대중적인 셸
기능 : sh의 기능 + 명령 히스토리(이전에 실행된 명령) 지원, Tab 자동 완성 지원, 
bash 로그인 시 시작 파일(/etc/profile, ~/.bash_profile, ~/.bash_logic, ~/.profile) 자동 실행,
bash 종료 시 종료 파일(~/.bash_logout) 자동 실행, 
셸에서 bash 실행 시 시작 파일(/etc/bash.bashrc, ~/.bashrc) 자동 실행

*실행과 로그인의 차이
실행 : 콘솔 창에서 bash 명령어를 실행하거나 스크립트 내부에서 bash를 호출하는 것
로그인 : 사용자가 아이디와 비밀번호 등을 입력해 셸을 접속하는 상황 (ex. secure shell(ssh)접속)

- ash & dash  
Almquist Shell(ash)과 Debian Almquist shell(dash)은 bash보다 경량화된 유닉스 셸
bash보다 가볍고, 라이브러리 의존성이 상대적으로 적음
플로피 디스크에 셸을 설치하는 상황, 루트 사용자의 셸, /bin/sh (sh) 대체용으로 주로 사용

- zsh  
Z Shell(zsh)은 Paul Falstad 가 최초로 작성한 유닉스 셸
Bourne Shell 기반으로, bash, ksh 등의 다양한 셸의 장점을 모아 만든 확장형 셸으로, 커스텀이 용이하며 설치가 간편함


## **4. 파일과 디렉터리**
- 파일(File)
의미가 있는 정보를 모아둔 논리적인 단위, 종이 문서의 묶음을 말하는 파일에서 유래됨
파일의 이름은 일반적으로 파일이름.확장자명으로 구성되는데, GUI 환경에서와 달리 CLI 환경에서는 큰 상관이 없다. 운영체제는 파일의 맨 처음 특정 bytes만큼을 읽어 구분하기 때문에 확장자명을 설정할 필요가 없음(매직 넘버(Magic number) 또는 파일 시그니쳐(File Signature) : 파일의 맨 앞에 특정 바이트로 해당 파일의 종류를 나타내는 값) 파일 이름만 보고 쉽게 구분할 수 있도록 .sh(셸 스크립트), .log(로그 파일) 같은 확장자를 붙이는 것이 일반적임

- 디렉토리(Directory)
파일을 분리하기 위해 사용하는 네임스페이스(Namespace)로, 윈도우 같은 환경에서는 주로 폴더라고 부름. 다른 디렉토리나 파일을 내부에 포함할 수 있으며, 포함되는 디렉토리를 하위 디렉토리(Child Directory / Sub Directory), 포함하는 디렉토리를 상위 디렉토리(Parent Directory)라 함. 디렉토리와 파일은 일반적으로 트리 구조를 형성함

![ ](/assets/images/tree.png)

![ ](/assets/images/tree2.png)

최상위 디렉토리는 / 로 표기하며, 그 하위 디렉토리는 /<directory1>/<directory2>와 같이 표기
- 절대 경로 : 어떤 폴더나 디렉토리의 경로를 최상위 디렉토리부터 표시한 경로
- 상대 경로 : 사용한 경로가 / 부터 시작하지 않는 경로

- ./ : 현재 사용자가 위치한 디렉토리의 위치를 위미
- ~/ : 사용자의 홈 디렉토리
- ../ : 상위 디렉토리

### 디렉토리 경로 확인(pwd)
pwd : print working directory의 약자로 현재 작업 중인 디렉토리를 출력

### 디렉토리 경로 변경(cd)
cd : change directory의 약자로 디렉토리 경로 변경
(ex. cd ../ : 현재 터미널의 폴더 위치를 이전 경로로 변경, cd ~ ,cd : 홈 디렉토리로 돌아감)

### 디렉토리 및 파일 확인(ls)
- ls : list segments의 약자로 파일 목록 표시
- ls --help : 구체적인 옵션 확인
- ls -al : 홈 디렉토리에 존재하는 모든 파일 및 디렉토리를 확인(-a + -l)
![ ](/assets/images/filecommand.png)

ls [옵션] [파일 경로] 형태로 주로 사용, 파일 경로 명시하지 않은 경우 해당 경로를 현재 디렉토리로 취급

### 디렉토리 생성(mkdir)
mkdir : make directory의 약자로, 새로운 디렉토리 생성, mkdir [디렉토리 이름] 형태로 사용

### 디렉토리 삭제(rmdir)
rmdir : remove directory의 약자로, 생성된 디렉토리 삭제, rmdir [디렉토리 이름] 형태로 사용

### 파일 생성(touch)
touch [파일 이름] 으로 새로운 파일을 생성하며, 여러 개의 파일을 한번에 생성하고 싶을 때는 touch [파일 이름1] [파일 이름2] ... 와 같이 사용

### 파일 읽기 및 쓰기(cat, head, tail)
cat : concatenate 에서 유래한 명령어로 두 내용을 연결한다는 뜻
- cat [파일 이름] : 파일과 터미널 입출력을 연결하게 되어 파일의 내용이 터미널에 출력됨
- cat > [파일 이름] : 터미널의 입출력과 파일을 연결하게 되며 터미널의 입력이 파일에 기록됨

- head : 파일의 앞쪽을 읽기, tail : 파일의 뒤쪽을 읽기
-c [bytes] 옵션을 사용하여 원하는 바이트만큼 읽어오거나 -n [개수] 옵션을 사용하여 원하는 줄 수 만큼 읽어올 수 있음

### 파일 이동 및 복사(mv, cp)
mv : move 의 약자로, 파일의 경로 변경, mv [옵션] [현재 경로] [변경할 경로] 형태로 사용
##### 옵션
- -b : 변경하고자 하는 경로에 동일한 파일명이 존재하면 백업 파일 생성
- -f : 변경하고자 하는 경로에 동일한 파일명이 존재하면 사용자에게 덮어씌우기 여부를 묻지 않고 강제로 덮어씀
- -i : 변경하고자 하는 경로에 동일한 파일명이 존재하면 사용자에게 덮어씌우기 여부를 물어봄
- -n : 변경하고자 하는 경로에 동일한 파일명이 존재하면 파일을 이동하지 않음

cp : copy 의 약자로, 파일을 복사, cp [옵션] [현재 경로] [복사할 경로] 형태로 사용
디렉토리에 cp를 사용하기 위해 -r 옵션 부여 필요
- -r : 하위 디렉토리의 내용까지 모두 복사
- -f : 복사하고자 하는 경로에 동일한 파일명이 존재하면 사용자에게 덮어씌우기 여부를 묻지 않고 강제로 덮어씀
- -i : 복사하고자 하는 경로에 동일한 파일명이 존재하면 사용자에게 덮어씌우기 여부를 물어봄
- -p : 파일 복사 시 모든 권한 정보를 함께 복사

### 파일 삭제(rm)
rm : remove 의 약자로, 생성된 파일 삭제, rm [옵션] [디렉토리 경로] 또는 rm [파일 이름] 형태로 사용
- -f : 강제로 파일이나 디렉토리 삭제
- -r : 삭제하고자 하는 경로의 하위 객체들을 재귀적으로 모두 삭제
- -d : 비어있는 디렉토리만 삭제
- -v : 삭제되는 대상 정보를 출력

### 파일 링크
링크 파일(Link File)은 어떤 파일들의 정보를 직,간접적으로 연결한 파일을 의미
파일 시스템(File System) : 운영체제가 파일들을 생성, 읽기, 쓰기 위해 필요한 시스템
inode : 파일 시스템이 각 파일들을 관리하는 메타 데이터, 각 파일은 고유한 inode르 가지고 있음
inode 번호, 파일 모드, 링크 개수, 소유자와 그룹 ID, 파일 크기와 주소, 파일 최종 접근, 수정 정보, inode 수정 정보, 데이터 저장 위치와 같은 정보를 포함함
참조 횟수(Reference Count, refcount)는 inode를 참조하고 있는 파일의 개수를 의미

#### - 하드 링크(Hard Link) 
생성되는 파일의 inode를 링크하고자 하는 파일에 직접 연결(이렇게 연결된 파일은 경로만 다를 뿐 사실상 동일한 파일임), 커널에서 이를 체크하고자 링크 개수를 1 증가 시켜 원본 파일이 삭제되어도 하드 링크된 파일은 여전히 링크한 파일의 내용에 접근할 수 있음

#### - 심볼릭 링크(Symbolic Link) 또는 소프트 링크(Soft Link)
절대 경로 또는 상대 경로로 된 다른 파일들을 참조하는 파일, 각자 inode를 가지고 refcount가 1임, 원본 파일이 삭제되면 더 이상 소프트 링크를 통해 원본 파일에 접근할 수 없음

ln : link 의 약자로, 링크 파일 생성, ln [옵션] [원본 파일] [링크 파일] 로 실행
- -b : 이미 생성하고자 하는 링크 파일과 동일한 이름의 파일이 존재하는 경우 백업파일을 만들고 링크파일 생성
- -d : 디렉토리의 하드링크 파일 생성 허용
- -f : 이미 생성하고자 하는 링크 파일과 동일한 일므의 파일이 존재하는 경우 기존 파일을 덮어씌움
- -s : 심볼릭 링크 파일 생성
- -n : 링크하고자 하는 원본 파일이 심볼릭 링크인 경우 원본 심볼릭 링크가 가리키고 있는 파일로 링크

### 파일 탐색(find)
find [옵션] [탐색 시작 경로] [표현식 1] [표현식 2] ... 로 사용, 탐색 시작 경로부터 시작해 표현식을 만족하는 파일 탐색
- -P : 탐색 중 심볼릭 링크 파일을 만나는 경우 심볼릭 링크 자체 정보를 사용
- -L : 탐색 중 심볼릭 링크 파일을 만나는 경우 심볼릭 링크에 연결된 파일의 정보를 탐색
- -H : 심볼릭 링크를 따라가지 않음
- -D [추가 옵션] : 추가 디버깅 옵션 사용
- -O[level] : 쿼리 최적화 수행

##### 주로 쓰는 표현식
-name [text], -user [text], -group [text], -uid [uid], -gid [gid], -perm [permission], -type [type], -maxdepth [depth], -mindepth [depth]
[text]에 와일드카드 사용 가능


## **5. 프로세스 생성 및 관리**
### 프로세스(Process)
컴퓨터에서 실행되고 있는 프로그램. 사용자 혹은 이미 실행되고 있는 프로세스가 실행 가능한 프로그램을 실행하고자 하는 경우 운영체제에 실행을 요청하며 운영체제는 이 명령을 받아 프로세스 생성. 생성된 프로세스는 CPU에서 실행됨
#### 5가지의 상태
- 생성(Create) : 프로세스가 생성 중
- 실행(Running) : 프로세스가 CPU를 점유하여 실제로 명령어 실행 중
- 준비(Ready) : 프로세스가 CPU를 점유하기 위해 대기하는 중
- 대기(Blocked) : 프로세스가 입출력 대기 혹은 리소스에 접근 불가 등의 이유로 요청한 일을 수행할 수 없어 CPU를 양도하고 선수 작업이 완료되기를 대기하는 중
- 종료(Terminated) : 프로세스가 종료되는 중

### 리눅스 프로세스
PID(Process ID)와 PPID(Parent Process ID)를 가짐, 프로세스의 아이디는 고유함
- PID : 현재 프로세스의 아이디
- PPID : 부모 프로세스의 아이디

새로운 프로세스를 생성할 때 fork() 를 사용해 현제 프로세스를 복제하여 새로운 프로세스를 생성하는데, 이때 최상위 프로세스가 유일하게 존재하며 이를 init 프로세스라 하며 PID는 1임
fork()로 프로세스를 생성하면 원본 프로세스를 부모 프로세스, 생성되는 프로세스를 자식 프로세스라 함
자식 프로세스에서 exec()을 사용하면 프로세스를 복제한 후 자식 프로세스의 내용을 다른 실행파일의 내용으로 덮어쓰게 됨.
부모 프로세스는 자식 프로세스를 수거할 책임이 있고, 부모 프로세스가 먼저 종료된다면 자식 프로세스는 고아 프로세스가 되고 이런 프로세스의 PPID는 1이 되어 부모 프로세스를 init으로 변경함
반대로 자식 프로세스는 종료되었지만 부모 프로세스가 종료된 자식 프로세스를 수거하지 않아 남아있게 되면 이를 좀비 프로세스라 부름, 일반적으로 일시적이고 부모에 의해 수거됨

#### 프로세스 확인(ps, htop)
ps : process state 의 약자로, 현재 실행중인 프로세스의 상태를 보여줌, ps [옵션] 으로 사용
- -A : 모든 프로세스 정보 출력
- -a : 세션 리더를 제외한 터미널에 종속적이지 않은 모든 프로세스 출력
- -e : 커널 프로세스를 제외한 모든 프로세스 출력
- -f : 정보 출력 시 풀 포맷 사용
- -l : 정보 출력 시 롱 포맷 사용
- -M : 64bit 프로세스 출력
- -m : 커널 스레드 출력
- -p [pid] : [pid]를 가지는 프로세스 출력
- -r : 현재 실행 중인 프로세스 출력
- -u [user] : [user]가 실행하는 프로세스 출력

![ ](/assets/images/pstable.png)

### 포그라운드와 백그라운드(fg, bg, jobs)
- 포그라운드 프로세스(Foreground Process) : 사용자와 직접적으로 상호작용하며 실행되는 프로세스, 직접 입력 하는 등 직접적인 상호작용 가능
- 백그라운드 프로세스(Background Process) : 사용자와 직접적으로 상호작용하지 않고 실행되는 프로세스, 사용자는 해당 프로세스의 입출력을 직접적으로 제어할 수 없음

- 정지(Stopped / Suspended) : 백그라운드에 있지만 실행되지 않는 경우

- jobs : 사용자가 셸을 통해 실행한 프로세스의 리스트와 그 순서를 출력
- fg : 정지된 프로세스나 백그라운드 프로세스를 포그라운드로 가져옴
- bg : 정지된 프로세스를 백그라운드에서 실행하도록 함
- & : 프로세스를 백그라운드에서 실행

### 프로세스 종료(kill, pkill)
kill -[signal] [PID] 로 사용하며 시그널이란 커널이 프로세스에게 보내는 특수한 신호로써 이 신호를 받는 즉시 프로세스는 기존에 수행하던 일을 중단하고 요청받은 시그널을 우선적으로 처리해야 함

### 프로세스 우선 순위(nice)
프로세스의 nice 값을 설정하여 우선 순위를 결정, 값의 범위는 -20~19로, 숫자가 낮을수록 우선순위가 높아짐. 기본값은 0이며, 일반 사용자는 값을 증가시키는 것만 가능하고, 슈퍼 유저는 임의로 값을 변경할 수 있음(renice)

### 프로세스 모니터링(htop)
htop : Hisham's top의 약자로, 프로세스를 모니터링하기 위해 사용하는 top을 Hisham Muhammad가 개량한 것

### 프로그램 실행 방법
셸에서 어떤 파일 경로를 입력했을 때 해당 파일의 파일 시그니처 확인 후 실행 가능한 파일이면 셸은 해당 프로그램을 exec()로 실행

### 실행파일 생성 및 실행
GCC(GNU Compiler Collection)와 같은 컴파일러를 이용해 코드를 실행파일로 바꾸어 가능
이 과정을 컴파일이라 하고 컴파일이 필요한 언어를 컴파일 언어(ex. C, C++, Java)라 함
컴파일 없이 실행 가능한 언어는 인터프리터 언어(ex. Python, JavaScript)라고 함


## **6. 환경 변수**
환경 변수(Environment Variable) : 컴퓨터에서 실행 중인 프로세스의 동작 방식에 영향을 미치는 값, 사용자가 임의로 정의 가능. 일반적으로 키-값(key-value) 쌍의 형태로 구성
특정 디렉토리 경로, 사용자 이름, 시스템 환경 설정, 또는 응용 프로그램이 참조할 API 키 등을 환경 변수로 지정할 수 있음

- PATH : 실행파일 탐색 경로 집합
- HOME : 사용자의 홈 디렉토리
- LANG : 터미널에서 기본적으로 지원할 언어
- PWD : 사용자의 현재 작업 디렉토리 경로
- USER : 사용자 이름
- SHELL : 로그인 셸 종류
- MAIL : 메일 보관 경로
- UID : 사용자의 UID
- LS_COLORS : ls 명령어 사용 시 출력되는 색상 옵션의 경로

### 환경 변수 확인(env)
- env : environ 의 약자로, 현재 환경 변수를 출력하거나 새로운 환경 변수를 설정한 후 해당 환경 변수로 프로그램을 실행하는데 사용, env [옵션] [NAME=VALUE(환경 변수)] [명령어] 으로 사용
- -i : 현재 환경 변수 설정을 모두 무시하고 지정한 환경 변수 값을 따름
- -u : 지정한 변수의 설정 값 해제
- env : 설정된 환경 변수 모두 보여줌

### 환경 변수 설정(export)
현재 셸에서 새로운 환경 변수를 생성할 때 사용, export [key=value(환경 변수)] 로 새로운 환경 변수 설정, export -p = env
환경 변수의 값에 접근하는 방법 : $[환경 변수 KEY]

### 환경 변수 삭제(unset)
현재 셸의 환경 변수를 삭제할 때 사용, unset [환경 변수 key] 로 사용


## **7. 파일 디스크립터**
### 파일 디스크립터(File Descriptor, fd)
프로세스가 파일을 열어 작업한다고 할 때, 텍스트 에디터 프로세스가 파일 생성이나 수정을 위해 운영체제에 그 파일을 위한 권한을 요청하면 운영체제는 파일 디스크립터라는 번호를 할당해 반환함 -> 프로세스는 fd를 이용해서 저장장치에 위한 파일에 접근 가능

프로그램이 실행되면 파일 디스크립터를 관리하는 Descriptor Table이 생성됨. 이는 Open File Description을 가리키고, 최종적으로는 inode table을 가리킴

프로세스는 기본적으로 0, 1, 2번 파일 디스크립터가 할당되어 있고, 각각 표준 입력(standard input(stdin)), 표준 출력(standard output(stdout)), 오류 출력(standard error(stderr))을 뜻함.
따라서 새로운 파일을 열면 fd가 3부터 할당됨

### Pipe(|)
이전 명령의 출력을 다음 명령어의 입력으로 제공, 명령어가 아님

### Redirection(>)
입력과 출력의 방향 재지정, 명령어가 아님

- <, << : 입력 방향 재지정
- \>, >> : 출력 방향 재지정(> : 덮어쓰기, >> : 기존 내용에 이어서 작성하기)
- [A] 2> [B] : A의 표준 에러를 B의 입력으로 리다이렉션
- [A] 2>&1 : A의 표준 에러를 표준 출력으로 리다이렉션
- [A] > [B] << [C] : A의 표준 출력을 B의 입력으로 리다이렉션하며 C라는 문자열이 입력으로 들어오면 리다이렉션을 중단하고, 이 때 C는 리다이렉션 내용에 포함되지 않음

### grep
vi의 명령어인 grep(global, regular expression, and print)의 약자에서 유래됨, 표준 입력에서 들어오는 내용들 중 정규식을 만족하는 문자열을 출력, grep [옵션] [패턴] [파일명/디렉터리명] 으로 사용

- -c : 문자열이 포함된 줄 개수 출력
- -o : 주어진 정규식에 맞는 내용만 출력(해당 옵션이 없는 경우 줄 전체 출력)
- -i : 문자열의 대소문자를 구분하지 않음
- -h : 파일 이름을 출력하지 않음
- -l : 문자열이 일치한 파일의 이름만 출력
- -v : 입력 패턴이 포함되지 않은 문자열 출력
- -r : 서브 디렉터리의 파일까지 모두 출력
- -n : 일치한 문자열이 포함된 줄 번호를 출력
- -w : 입력한 문자열이 독립된 단어로써 존재하는 경우만 출력

[명령어] | grep [매칭 문자] 형식으로 많이 사용 -> 명령어의 출력 결과에서 원하는 문자열을 찾기 위해 사용
grep [찾을 내용] [파일 이름] 패턴에 정규식을 사용 가능


## **8. 사용자와 그룹**
### 리눅스 권한 관리 방식
#### 유저와 그룹
유저(u, user)와 그룹(g, group)을 가짐.
- 유저 정보는 /etc/passwd에 저장됨, 각 문자열은 [이름]:[암호]:[UID]:[GID]:[추가정보]:[홈 디렉터리]:[기본 셸] 포맷을 만족함
암호는 x인 경우 /etc/shadow에 따로 암호 저장, root에서만 sudo cat /etc/shadow로 읽을 수 있음
[이름]:[암호화 값]:[수정 일자]:[최소 사용 기간]:[최대 사용 기간]:[경고 기간]:[만기일]:[차단 기간]:[reserved]포맷을 만족함. 이때 암호화 값은 $[id]$[salt]$[hash]의 형태이며, id : 해싱 알고리즘, salt : 해시 시 salt 값, hash : password와 salt를 id에 해당하는 해싱 알고리즘으로 해싱 시 결과, * : 어떤 password도 대응되지 않음
- 그룹 정보는 /etc/group에 저장됨, 각 문자열은 [이름]:[암호]:[GID]:[멤버] 포맷을 만족함.
그룹도 유저와 마찬가지로 암호는 /etc/gshadow에 따로 저장되고, root에서만 sudo cat /etc/gshaow로 읽을 수 있음, [이름]:[암호]:[관리자]:[멤버] 포맷을 만족함

#### 리눅스 파일 권한
소유자(u, user), 그룹(g, group), 일반 사용자(o, other) 주체 각각에 대해 읽기(r, read, 4), 쓰기(w, write, 2), 실행하기(x, execute, 1) 3가지 권한을 부여함. 숫자로 표현한 권한을 이진수로 표현하면 0b100, 0b010, 0b001 이고, 각 비트를 비트플래그(bitflag)로 생각하여 사용함.

### 유저 관리
#### 유저 생성(useradd, adduser)
계정 생성은 root만 가능, useradd [옵션] [유저 이름] 또는 useradd [유저 이름] [옵션] 으로 사용함
adduser은 다양한 설정을 편리하게 수정할 수 있어 일반적인 경우 이를 사용하여 계정 생성, sudo adduser [유저 이름]을 입력하면 계정이 생성됨

#### 유저 관리(usermod, passwd)
유저 정보 변경 가능, root만 사용 가능, usermod [옵션] [유저 이름] 또는 usermod [유저 이름] [옵션] , passwd [유저 이름] 으로 사용

- -p [암호] : 사용자의 암호를 추가 시에 지정
- -d [경로] : 변경할 홈 디렉터리 지정
- -u [UID] : 사용자의 UID 변경
- -g [GID] : 사용자의 GID 변경
- -c [설명] : 사용자의 추가 설명 변경
- -s [셸 경로] : 사용자의 기본 셸 변경
- -m : 홈 디렉터리 변경 시 기존에 사용하던 파일 및 디렉터리 옮김
- -f [일] : 패스워드의 만기일 변경
- -e [날짜] : 계정의 만기일 변경
- -l [유저 이름] : 사용자의 유저 이름 변경
- -L : 사용자가 로그인하지 못하도록 패스워드에 잠금
- -U : 사용자의 패스워드 잠금 해제

#### 유저 삭제(userdel, deluser)
userdel [옵션] [유저 이름] 또는 userdel [유저 이름] [옵션] 으로 사용
- -f : 강제로 사용자 삭제 
- -r : 사용자의 홈 디렉터리 함께 삭제

### 그룹 관리
#### 그룹 생성(groupadd, addgroup)
groupadd [옵션] [그룹 이름] 또는 groupadd [그룹 이름] [옵션] 으로 사용
-g [GID] : 생성할 그룹의 GID 지정

#### 그룹 정보 변경(groupmod)
groupmod [옵션] [그룹 이름] 또는 groupmod [이름] [그룹 이름] 으로 사용
- -n [그룹명] : 기존 그룹명을 새로운 그룹명으로 변경
- -g [GID] : 기존 GID를 새로운 GID로 변경

#### 그룹 관리(gpasswd)
gpasswd [옵션] [그룹 이름] 또는 gpasswd [이름] [그룹 이름] 으로 사용
- -r : 그룹 패스워드 설정
- -R : 그룹 사용을 금지
- -a [유저 이름] : 그룹에 사용자 추가
- -A [유저 이름] : 사용자를 그룹 관리자로 지정
- -d [유저 이름] : 그룹에서 사용자를 삭제
- -M [유저 이름] : 그룹 사용자를 초기화하고 해당 사용자를 그룹에 추가

#### 그룹 삭제(groupdel, delgroup)
groupdle [옵션] [이름] 또는 groupdel [이름] [옵션] 으로 사용
- -f : 강제로 그룹 삭제

### 소유자, 그룹 및 권한 변경
#### 그룹 변경(chgrp)
chgrp : change group 의 약자로, 폴더나 디렉터리의 그룹을 변경할 때 사용, chgrp [옵션] [소유 그룹] [파일/디렉터리 이름]으로 사용
- -c : 그룹이 변경된 파일의 정보를 자세히 보여줌
- -f : 권한 등의 이유로 그룹이 변경되지 않은 경우에 오류를 출력하지 않음
- -v : 변경 상태를 자세히 보여줌

#### 소유자, 그룹 변경(chown)
chown : change owner의 약자로, 폴더나 디렉터리의 소유자와 소유 그룹을 변경할 때 사용, chown [옵션] [소유자:소유 그룹] [파일/디렉터리 이름] 으로 사용
- -c : 소유자가 변경된 파일의 정보를 자세히 보여줌
- -f : 권한 등의 이유로 소유자가 변경되지 않은 경우에 오류를 출력하지 않음
- -v : 변경 상태를 자세히 보여줌

#### 권한 변경(chmod)
chmod : change mode 의 약자로, chmod [옵션] [권한] [파일/디렉터리 이름] 으로 사용
- -c : 권한이 변경된 파일의 정보를 자세히 보여줌
- -f : 권한이 변경되지 않은 경우 오류를 출력하지 않음
- -v : 변경 상태를 자세히 보여줌

권한은 [특수 권한] [소유자 권한] [그룹 권한] [일반 권한] 순서로 적음
ex. 소유자 권한이 RWX, 그룹 권한이 R-X, 일반 권한이 W인 파일에 setuid가 걸려있도록 설정하고 싶은  경우, -rws-r-x-w-로 쓰며 숫자로는 4752라고 함
숫자 대신 문자로 권한을 표기할 수도 있으며 이 경우 [객체][+/-][권한] 형태로 표기함

### 유저 변경(su)
su : substitute user 의 약자로, 다른 유저로의 전환을 위해 사용, 사용자를 지정하지 않는 경우 root를 의미, su [옵션] [유저 이름] 으로 사용
- -c [명령어] : su의 유저 권한으로 명령어를 실행 
- -/ -l : su로 지정한 유저의 환경 변수를 적용하여 로그인
- -s [셸] : 지정된 셸로 로그인

### 유저 변경 및 실행(sudo)
sudo : substitute user do로 현재 계정에서 다른 계정의 권한을 빌려 명령 수행, 사용자를 지정하지 않는 경우 root 권한으로 실행, sudo [옵션] [명령어] 로 사용
- -b : 백그라운드에서 명령 실행
- -C [fd] : fd보다 크거나 같은 모든 파일 디스크립터를 닫음
- -e : [명령어] 대신 [파일]을 사용, 파일을 지정한 권한으로 수정
- -g [GID/그룹 이름] : 지정한 그룹으로 명령어 실행
- -u [UID / 유저 이름] : 지정한 사용자로 명령어 실행
- -s : 지정한 사용자로 셸 실행
- -i : 지정한 사용자로 로그인 셸 실행

*sudo는 [명령어] 의 권한을 바꾸어 실행하기 때문에 올바르게 권한 설정이 적용되지 않을 경우, tee [파일 이름] 형태로 사용
